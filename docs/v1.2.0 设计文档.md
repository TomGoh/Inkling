## 任务 P1：插件回调加 docChanged 守卫

### 目标
消除每次按键/光标移动时的无谓全树遍历。formula-numbering / block-drag / outline 等插件的回调在纯选区变化（非 doc 变更）时不应触发 O(N) 计算。

### 技术方案

修改 [formula-numbering.ts](file:///workspace/src/components/Editor/formula-numbering.ts)：

```typescript
// 原实现：每个 transaction（含纯光标移动）都全树 descendants
appendTransaction: (_trs, _old, newState) => {
  const tr = recalcNumbers(newState);
  return tr ?? null;
}

// 优化后：仅在 docChanged 或收到 recalc meta 时执行；无公式节点直接短路
appendTransaction: (trs, _old, newState) => {
  const docChanged = trs.some((t) => t.docChanged);
  const hasRecalcMeta = trs.some((t) => t.getMeta(formulaRecalcKey));
  if (!docChanged && !hasRecalcMeta) return null;
  if (!hasMathDisplay(newState.doc)) return null;
  const tr = recalcNumbers(newState);
  return tr ?? null;
}
```

- 新增 `hasMathDisplay(doc)` 短路检查：用 `doc.rangeHasType` 或快速 descendants 判断是否存在 math_display 节点，无则跳过编号计算。
- 功能开关切换时，由 [Editor.tsx](file:///workspace/src/components/Editor/Editor.tsx) 在 settings 变化 effect 中 dispatch 一个空 tr 并带 `formulaRecalcKey` meta 显式触发重算，避免依赖「任何 tr 都跑」的旧逻辑。

修改 [block-drag.ts](file:///workspace/src/components/Editor/block-drag.ts)：

```typescript
// 原实现：decorations 每次状态变化都重建所有块的手柄
decorations: (state) => buildHandleDecorations(state)

// 优化后：缓存到 plugin state，仅在 doc 变更或 dropIndex 变化时重建
decorations: (state) => {
  const cached = blockDragKey.getState(state);
  if (cached && cached.docEq === state.doc && cached.dropIndex === currentDropIndex(state)) {
    return cached.decorations;
  }
  return buildHandleDecorations(state);
}
```

修改 [outline.ts](file:///workspace/src/lib/outline.ts) 的 `findActiveHeadingIndex`：从 O(n) 线性扫描改为 O(log n) 二分查找，并加首尾短路（选区在第一个标题之前返回 null，在最后一个标题之后返回最后一个）。

## 任务 P2：cursor-saver 防抖落 store

### 目标
光标位置记忆插件（`inkling-cursor-saver`）原本每次光标移动都 `set({ openTabs })`，导致订阅 `openTabs` 的 TabsBar 和 useAutoSave 在打字过程中持续重渲染。

### 技术方案

修改 [Editor.tsx](file:///workspace/src/components/Editor/Editor.tsx) 的 cursor-saver 插件：

```typescript
// 闭包内缓存最新位置，防抖 300ms、失焦、销毁时才写 store
let pendingPos: number | null = null;
let pendingScroll = 0;
let debounceTimer: ReturnType<typeof setTimeout> | null = null;

const flush = () => {
  if (pendingPos === null) return;
  saveCursorStateRef.current(pendingPos, pendingScroll);
  pendingPos = null;
};

new Plugin({
  key: new PluginKey("inkling-cursor-saver"),
  view: () => ({
    update: (view) => {
      pendingPos = view.state.selection.head;
      const scrollEl = (view as EditorView & { scrollDOM?: HTMLElement }).scrollDOM;
      pendingScroll = scrollEl ? scrollEl.scrollTop : 0;
      if (debounceTimer) clearTimeout(debounceTimer);
      debounceTimer = setTimeout(flush, 300);
    },
    destroy: () => {
      if (debounceTimer) clearTimeout(debounceTimer);
      flush();
    },
  }),
}),
```

同时让 editor DOM 监听 `blur` 事件触发 `flush`，确保切换 tab 时不丢位置。

## 任务 P3：TabsBar / useAutoSave 精准订阅

### 目标
打字时 content 变化不应触发 TabsBar / useAutoSave 重渲染。

### 技术方案

修改 [TabsBar.tsx](file:///workspace/src/components/Tabs/TabsBar.tsx)：

```typescript
// 原实现：订阅整个 openTabs 数组，content 变化也触发重渲染
const openTabs = useWorkspace((s) => s.openTabs);

// 优化后：订阅派生的字符串快照，仅 path/dirty/isUntitled 变化才重渲染
const tabsSnapshot = useWorkspace((s) =>
  s.openTabs.map((t) => `${t.path}|${t.dirty ? 1 : 0}|${t.isUntitled ? 1 : 0}`).join("\n"),
);
```

修改 [useAutoSave.ts](file:///workspace/src/lib/useAutoSave.ts)：

```typescript
// 原实现：订阅 currentContent，每次按键都重新订阅
const content = useWorkspace((s) => s.currentContent);

// 优化后：订阅「活跃 tab 是否未命名」布尔派生值
const activeIsUntitled = useWorkspace((s) => {
  const tab = s.openTabs.find((t) => t.path === s.activeTabPath);
  return tab?.isUntitled ?? false;
});
```

## 任务 P4：代码块 NodeView 视口懒挂载

### 目标
大量代码块文档避免一次性初始化上百个 CodeMirror 实例。

### 技术方案

修改 [code-block-view.ts](file:///workspace/src/components/Editor/code-block-view.ts)：

```typescript
// 用 IntersectionObserver 监听代码块 DOM 进入视口（200px 预加载）
let cmInstance: EditorView | null = null;
let io: IntersectionObserver | null = null;

function ensureCM(dom: HTMLElement, node: Node) {
  if (cmInstance) return;
  cmInstance = createCodeMirror(node, node.textContent ?? "");
  // 同步 node 最新内容
  syncNodeToCM(cmInstance, node);
}

// NodeView mount 时：
io = new IntersectionObserver(
  (entries) => {
    if (entries[0]?.isIntersecting) {
      ensureCM(dom, node);
      io?.disconnect();
      io = null;
    }
  },
  { rootMargin: "200px" },
);
io.observe(dom);

// update 在 cmInstance 未创建时仅更新 node 引用，不创建实例
update(updatedNode: Node) {
  node = updatedNode;
  if (cmInstance) syncNodeToCM(cmInstance, node);
}

// destroy 时清理 IO 和 CM 实例
destroy() {
  io?.disconnect();
  cmInstance?.destroy();
}
```

const debouncedFind = useDebounce(find, 120);

## 任务 P6：Ctrl+R 替换快捷键

### 目标
绑定 Ctrl+R 打开查找替换面板并自动展开替换框。

### 技术方案

修改 [SearchPanel.tsx](file:///workspace/src/components/Editor/SearchPanel.tsx)：`showReplace` 由内部 state 改为受控 props。

```typescript
interface Props {
  getEditor: () => Editor | undefined;
  onClose: () => void;
  showReplace: boolean;              // 受控
  onShowReplaceChange: (v: boolean) => void;
}
```

修改 [App.tsx](file:///workspace/src/App.tsx) 全局快捷键 handler：

```typescript
const [searchOpen, setSearchOpen] = useState(false);
const [searchShowReplace, setSearchShowReplace] = useState(false);

// Ctrl/Cmd+R 打开替换面板
if (!e.shiftKey && !e.altKey && e.key.toLowerCase() === "r") {
  e.preventDefault();
  setSearchShowReplace(true);
  setSearchOpen(true);
  return;
}

// Ctrl/Cmd+F 打开查找面板（不展开替换框）
if (tryMatch("find")) {
  e.preventDefault();
  setSearchShowReplace(false);
  setSearchOpen(true);
}
```

渲染 SearchPanel 时传入受控 props：

```tsx
{searchOpen && (
  <SearchPanel
    getEditor={getEditor}
    onClose={() => setSearchOpen(false)}
    showReplace={searchShowReplace}
    onShowReplaceChange={setSearchShowReplace}
  />
)}
```

替换能力复用已实现的 [search.ts](file:///workspace/src/components/Editor/search.ts)：
- `replaceCurrent(view)`：替换当前高亮匹配
- `replaceAll(view)`：从后往前替换所有匹配（避免位置偏移），返回替换数量

## 客观定位：与主流编辑器性能对比

### 架构对比

| 维度 | InklingMD v1.2.0 | Typora | Obsidian | MarkText |
|------|-------------------|--------|----------|----------|
| 外壳 | Tauri（系统 WebView） | 自研 | Electron | Electron |
| 编辑内核 | ProseMirror/Milkdown | 自研优化 | CM6 + Live Preview | Muya + marked.js |
| 更新机制 | 增量 transaction | 自研增量 | 增量解析+节流 | **全量 re-parse** |
| 长文档渲染 | 全量 DOM（无虚拟化） | 懒渲染/按需布局 | 部分虚拟化 | 全量 DOM |
| 每键开销 | 已优化（守卫+防抖+懒挂载） | 极致精简增量 | 增量 | 全量 re-parse（卡顿根源） |

### 各场景体感差距

| 场景 | 与 Typora | 与 MarkText |
|------|-----------|-------------|
| 千行内日常写作 | 几乎无差距 | 明显优于 |
| 三五千行技术文档 | 轻微差距 | 明显优于 |
| 万行+长文档 | 明显差距（无虚拟滚动） | 优于（增量 vs 全量） |
| 含大量图表/公式 | 明显差距（无渲染缓存） | 持平 |
| 启动/内存 | 持平 | 远优（Tauri vs Electron） |

### 仍存在的架构限制（非本版范围）

1. ProseMirror 全量 DOM 渲染（无虚拟滚动）——长文档 DOM 节点数线性增长
2. Milkdown `markdownUpdated` 每键全文序列化 O(N)——受内核设计约束
3. Mermaid/KaTeX 无渲染缓存——含大量图表的长文档首屏重

追平 Typora 的长文档表现需 ProseMirror 装饰级虚拟化或 Mermaid/KaTeX 渲染缓存，属较大改造，留待后续版本评估。
