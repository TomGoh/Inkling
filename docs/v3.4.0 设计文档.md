## 1. 版本定位

本版本交付 **智能粘贴（Smart Paste）**，把「从别处复制一段内容粘进编辑器」从「丢格式」变成「结构化落盘」：

- 从**网页 / Word / Google Docs** 复制的富文本 → 转成标准 Markdown 结构，而不是一堆带颜色的 `span`；
- 从 **VS Code / GitHub README / 另一个 `.md`** 复制的 Markdown **源码** → 自动渲染成富文本，而不是把 `#` `**` 原样插进来；
- 粘贴内容里的**远程图片** → 后台下载并写入文档同目录的 `assets/`，按内容哈希去重，不产生副本也不留下失效外链。

同时本版本收口了 Smart Paste 落地后暴露的一整串**列表 / 任务项往返保真**问题（#248–#290），以及性能回归防线的一个系统性缺陷：**「同一场景两轮超阈值即判 FAIL」会被共享 runner 的并发争用骗过**（#270 / #274 / #285 / #291 / #294）。

## 2. Smart Paste 总体设计：两条输入、一条出口

三个子项共用一条出口：

```
剪贴板 text/html  ── sanitizeHTML(paste 模式) ──► htmlToMarkdown ─┐
                                                                  ├─► Milkdown parser ──► Slice ──► 文档
剪贴板 text/plain ── looksLikeMarkdown(≥2 类信号) ────────────────┘                          └─► 远程图片入后台队列
```

**为什么统一收口到 Markdown 文本**：写盘形态由 Milkdown serializer 统一生成，中间态只是「临时的 Markdown 文本」。因此转换阶段的转义可以「宁多勿少」——`\_` 与 `_` 解析结果相同，多余的反斜杠不会泄漏进用户文件。同理，HTML 路径只需要产出**能被 Milkdown 解析器正确还原的**结构，不必产出「最终写盘文本」。

**安全顺序不可交换**：`sanitizeHTML` **必须**在 `htmlToMarkdown` 之前。粘贴路径是本特性最大的攻击面（内容完全来自外部），结构映射只处理**已清洗**的 DOM，映射器本身不做任何安全判断——这样「清洗规则」只有一个真值源。

**主线程保护**：两条输入各有上限，且都必须在 ProseMirror 的 `readHTML` / `parseSlice` **之前**生效，否则保护形同虚设——HTML 路径 5,000 元素、Markdown 文本路径 64K 字符（`SCAN_LIMIT`）。

**一次粘贴 = 一个撤销步**：粘贴事务前后都 `closeHistory`，不与相邻输入合并成同一撤销组；远程图片替换 `src` 的事务 `addToHistory=false`，不额外增加撤销步。

## 3. 子项 A：网页 / 富文本 HTML → Markdown（#219，PR #244）

### 3.1 新增模块

| 文件 | 职责 |
|---|---|
| `src/components/Editor/html-to-markdown.ts` | HTML DOM → 中间态 Markdown（纯函数、只读 DOM、可对 fixture 快照） |
| `src/components/Editor/html-view.ts`（改） | `sanitizeHTML` 新增 `paste` 模式；`isSafeUrl` 相对路径判定加固 |
| `src/components/Editor/smart-paste.ts`（新） | 粘贴链路接线：路由判定 + Slice 构造 + 撤销步收口 |

### 3.2 `sanitizeHTML` 的 paste 模式（复用白名单，不重写）

- 危险标签（`script` / `style` / `iframe` / `object` / 表单控件…）**连同内容整棵丢弃**；
- 未知**块级**容器改写为 `div`，未知**行内**标签拆包保留子节点——这正是转换器「无法映射的块级容器：递归取子节点」的前置条件；
- 相对链接保留（与 Typora 一致）；粘贴内容不进渲染缓存；渲染模式行为不变。
- `isSafeUrl` 的相对路径判定**先剔除 C0 控制字符与空白**，堵住 `java\nscript:` 这类写法被当成相对路径放行。

### 3.3 结构映射与降级规则

支持：段落 / 换行、H1–H6、粗斜删 / 行内代码（含 Google Docs、Word 的 `span` 样式）、有序 / 无序 / 任务 / 嵌套列表、引用、链接 / 图片、代码块（识别 `language-x` / `lang-x` / `highlight-source-x`）、GFM 表格、水平线、HTML 实体。

显式降级（写在模块头，作为契约）：

| 输入形态 | 处理 |
|---|---|
| `colspan` / `rowspan` > 1 | 降级为普通单元格，合并信息丢弃（GFM 表格不支持合并） |
| 嵌套列表 > 6 层（`MAX_LIST_DEPTH`） | 更深的项提升为第 6 层的**兄弟项**（内容不丢，只丢层级） |
| 无语言标识的 `<pre>` | 输出无语言围栏 |
| 布局表格（单元格内嵌表格/标题/列表/代码块，或只有一个单元格） | 不转 GFM 表格，按块展开 |
| 无法映射的块级容器 | 递归取子节点 |

**强调定界符按 CommonMark flanking 规则处理**：行内构建期用私有区字符占位（`STRONG_OPEN/CLOSE`、`EM_OPEN/CLOSE`、`DEL_OPEN/CLOSE`），等拿到真实的左右邻居字符后再决定落成 `**` / `*` / `~~`。这样 `**注意：**这是` 这类「定界符右侧紧跟非空白」的形态与「左侧是标点」的形态都能正确处理。

### 3.4 私有区字符「去哨兵化」（#244 review）

转换器内部用 **U+E000–U+E006** 做占位，而图标字体 / Nerd Fonts 也把图标放在这段私有区码位。粘贴内容自带这些字符时会被静默改写：`<p>前&#xE001;后</p>` → `前**后`、`<p>前&#xE000;后</p>` → 硬换行。受影响的不止正文，还有行内代码、图片 `alt`、`title`、链接地址。

修复：所有**来自页面**的字符串在进入行内构建前先编码为字符引用 `&#xE001;`（Markdown 解析后还原为原字符——图标不丢失，优于直接替换成 U+FFFD）；**行内代码只能替换为 U+FFFD**，因为 CommonMark 不解码代码 span 内的字符引用；**代码块不经过行内构建**，原样保留。源码里不可见的私有区字符与不间断空格统一改写为 `\uXXXX` 转义，便于 review 看清占位符。

### 3.5 接线：`transformPastedHTML` 阶段接管

`transformPastedHTML(html, view)` 在 ProseMirror 解析前接管：

1. 判定路由 `routeHtmlPaste(html, text, types)`（纯函数，便于单测）：

| 路由 | 条件 | 动作 |
|---|---|---|
| `default` | 无 HTML / 含 `data-pm-slice`（编辑器内部复制）/ 非粘贴事件（拖放） | 交还 ProseMirror 默认处理 |
| `markdown-text` | `vscode-editor-data`，或清洗后只含 `div/span/p/br` 与无语言标识 `pre`/`code` 的**源码视图形态** | 按 `text/plain` 的 Markdown 源码解析 |
| `plain-text` | 元素数 > 5,000 | 整体降级为纯文本 |
| `convert` | 其余 | `htmlToMarkdown` → Markdown 中间态 |

2. 接管时**返回空串**，让默认解析零成本——5,000 元素的主线程保护必须在这一步之前生效。准备好的 Slice 暂存，由同一次 `doPaste` 内的 `handlePaste` 派发。

**块边界语义**（`sliceForInsertion`）：只有首 / 尾块是**段落**时才「打开」该端，让它与光标所在段落合并（行内粘贴的自然语义）；标题、列表、代码块、表格保持闭合、作为独立块插入——否则 `Slice.maxOpen` 会把首个标题的文字并进当前段落，标题语义丢失。

**不转换的情形**：编辑器内部复制（`data-pm-slice`，ProseMirror 自带序列化能无损还原）、代码编辑器 / IDE 的无结构着色 HTML、光标在代码块内（默认路径按纯文本插入）、光标在表格内（交 `prosemirror-tables`）、源码模式（CodeMirror 本就只收纯文本）、「粘贴为纯文本」。

**「粘贴为纯文本」快捷键**：新增可自定义项 `pastePlainText`，默认 `mod+shift+v`。原生就会派发该组合 `paste` 事件的平台走事件路径；不派发的平台（macOS WKWebView）兜底读剪贴板，并**吞掉迟到的原生 paste**（500ms 窗口）防止重复粘贴。

**安全**：解析结果统一经 `stripUnsafeUrls` 剥离 `javascript:` 等危险链接 / 图片地址（相对路径保留）。

## 4. 子项 B：Markdown 源码粘贴自动解析（#229，PR #245）

### 4.1 特征判定 `markdown-detect.ts`

**判据：命中至少 2 类独立信号**（`MIN_MARKDOWN_SIGNALS = 2`）。宁可漏判也不误判——误判会把用户的纯文本悄悄改写成富文本结构。

14 类信号：`heading` / `fence` / `bulletList` / `orderedList` / `taskList` / `blockquote` / `table` / `hr` / `mathBlock` / `bold` / `strike` / `inlineCode` / `link` / `image`。

三处刻意设计，避免「一类内容凑出两个信号」：

- **任务列表单独成类**：否则一行 `- [ ] x` 会同时计入无序列表；
- **`* * *` 这类分隔线不计为列表**（正则用负向前瞻排除）；
- **表格必须有分隔行**（`| --- | :-: |`），只有竖线的行不算；
- 图片的 `[alt](src)` 部分不再算一次链接。

只扫描前 **64KB**（`SCAN_LIMIT`）——信号判定不需要读完超大文本。

### 4.2 解析出口与上下文

`clipboardTextParser` 在判定成立时走与 HTML 路径**完全相同**的「Markdown → parser → Slice」出口，块边界语义一致；否则返回 `null`，走 ProseMirror 默认纯文本行为。

`vscode-editor-data` 与其他代码编辑器的无结构着色 HTML：`text/plain` 是 Markdown 时按 Markdown 解析，否则仍交还默认处理。

### 4.3 长度上限（#245 review）

文本路径此前没有与 HTML 路径（5,000 元素）对等的主线程保护。实测（Chromium，dev 构建）：

| 输入 | 耗时 |
|---|---|
| 真实文档（CHANGELOG，约 40K 字符） | ≈0.3 s |
| 代码块 / 表格密集的最坏情况 64K | ≈1.7 s |
| 同上 128K | ≈3.7 s |
| 同上 160K | **≈6 s（卡死）** |
| 1.1M | **OOM** |

修复：`MAX_MARKDOWN_PASTE_CHARS = SCAN_LIMIT`（64K UTF-16 码元），**使判定与解析同一上界**；超出时返回 `null` 按纯文本粘贴。超限后的耗时与上游 main 的纯文本粘贴同量级（72K/160K/400K 分别 ≈751/2436/16776ms，main 为 656/2638/15992ms——剩余耗时是 ProseMirror 默认纯文本粘贴处理数万短行段落的既有成本）。

另外修正：**仅在粘贴事件中解析**——ProseMirror 的拖放也会调用 `clipboardTextParser`，此前会隐式改变拖放行为，现已恢复原行为。

## 5. 子项 C：远程图片落盘 + 内容哈希去重（#220，PR #246）

补 `image-upload` 的三个缺口：

1. 剪贴板只有 `text/html` 的 `<img src>`、没有 `files`（macOS / 部分浏览器）时图片**永不落盘**；
2. 网页富文本里的远程图片没有下载转存；
3. 重复粘贴同一张图产生多份副本。

### 5.1 Rust 侧

| 命令 | 设计与约束 |
|---|---|
| `download_remote_image` | 前端受 CSP（`connect-src` 回落 `'self'`）与 CORS 约束无法直接 `fetch` 第三方图片，只能后端下载。只接受 http/https；重定向 ≤5 次且只在 http/https 之间跳；**不发送 Referer**（与 #162 的 `no-referrer` 一致）；单图 ≤10MB，**流式读取、超限立即中止**（不先把整个响应读进内存）；总超时 15s；按**魔数**识别位图格式，**SVG 一律拒绝**（可含脚本，落盘后在其他查看器打开有 XSS 风险）、HTML 错误页等非图片内容拒绝；403 单独标记以便提示防盗链 |
| `find_asset_by_hash` | 先按大小过滤、再对同尺寸文件算 SHA-256；只看目录**直接子文件**、不跟随符号链接 |

依赖取向：`reqwest` 沿用 Tauri 已依赖的 0.13，TLS 取 **rustls + ring + 系统信任库**——不引入 aws-lc 的 cmake/NASM 构建链，也不依赖系统 OpenSSL，保持跨平台构建简单。

错误标记（`REMOTE_IMAGE_*`）与前端 `src/lib/fs.ts` 保持契约一致，由 `mapRemoteImageError` 映射为用户可读提示（`forbidden` / `timeout` / `too-large` / `not-image` / `bad-url` / `http-status` / `svg` / 网络错误）。

### 5.2 前端侧

- **`lib/assetStore.saveImageAsset`**：文件型粘贴 / 拖拽与远程下载**共用**的写入入口。落盘前按（大小 + SHA-256）在目标 `assets/` 查重，命中即复用文件名。**查重是尽力而为**——查重失败（目录无权限、IPC 异常）不阻断插入，多一份副本远好于图片插入失败。
- **`remote-image` 插件**：
  - 图片先以远程 URL **即时插入**（粘贴即时可见，不被网络阻塞），随后后台**并发 3** 下载并替换为 `assets/` 相对路径；
  - 位置记在插件 state 里，随每个事务 `mapping.mapResult` 映射；**替换前再校验「该位置仍是 `src` 相同的图片节点」**——用户中途删改不会误伤其他内容；
  - `src` 替换事务 `addToHistory=false`，**一次粘贴仍是一个撤销步**；
  - 单次粘贴最多下载 30 张（`MAX_REMOTE_IMAGES_PER_PASTE`），超出保留远程引用；
  - 失败 / 超时 / 超限 / 403 时**保留远程 URL**（不产生空引用），汇总后一次性提示（写盘失败与下载失败分开描述）；
  - SVG、`data:`、相对路径、未保存草稿（没有 `assets/` 目录）不下载；
  - 落盘后的相对路径渲染时经 `resolveImageSrc` 触发动态 `allow_asset_dir` ACL 放行。
- **历史回放重新入队（#251，PR #258）**：撤销发生在下载完成前时，回放出的切片仍是远程 URL。用「**计数差**」找出相对上一状态**多出来**的远程图片重新入队（同一地址被多次粘贴、只回放其中一份时也正确），**文档自带的远程引用不会被误伤**。历史回放代数只在 `docChanged` 的历史事务上 +1，`view.update` 据此只处理一次；投递延后到微任务避免重入。
- 浏览器 mock 补齐 `fetch` 模拟下载与内存二进制表模拟落盘 / 查重，使 E2E 可覆盖。

## 6. 列表 / 任务项往返保真（#248–#290）

Smart Paste 让「外来 HTML → Markdown → 解析 → 再写盘」这条往返路径变成高频操作，于是把它此前被掩盖的一族问题全部暴露出来。这些问题的共同修复手段是**不可见的 `<!-- -->` HTML 注释作锚点**——它在渲染侧零可见内容，却是能打断段落、闭合列表、给任务标记提供依附的合法 Markdown 块。

| issue | PR | 现象与根因 | 修法 |
|---|---|---|---|
| #248 | #255 | 表格单元格内链接 / 图片的目标与标题（含 `alt` 中的 `|`）被拆裂 GFM 列结构 | 单元格内转义 `|`（含代码 span 内） |
| #249 | #256 | 相邻同型列表被 CommonMark 并成一个，边界与编号丢失 | 顶层与引用块两处拼接点插入 `<!-- -->` 分隔 |
| #264 | #265 | 列表项内**相邻同型子列表**同样被并成一个 | 列表项内各块的拼接此前绕开了 `joinBlocks`，抽出 `itemBlockSeparator` 补分隔 |
| #266 | #267 | `<ol start="3">` 子列表被吞成正文；空子列表项的 `-` 成 setext 下划线把父项正文变成 H2 | 「上一块是正文、本块是不能打断段落的列表」时改用 `\n<!-- -->\n`；并修正 `listBlockKind`：首项为空时输出裸标记 `-` / `3.`，原正则要求标记后有空格而漏判 |
| #268 | #269 | 首块是子列表的列表项保存后写出字面 `<br />`，且重开变成松散项 | 见 §6.1 |
| #272 | #278 | 空列表项保存后写出 `* <br />` | 见 §6.2 |
| #273 | #279 | 任务列表项的块级首块与 `[ ]` 标记同行 → 整行退化成正文、子列表丢失 | 标记独占一行并补空段落锚点 `- [ ] <!-- -->` |
| #284 | #287 | 空任务项用**空值**锚点 → mdast 正则匹配不上 → **checkbox 整块丢失** | 任务项改用**非空**锚点 `<!-- -->` |
| #286 | #289 | 「空任务项 + 子列表」命中 #268 剔除规则 → `head.type` 不是段落 → 勾选项**永久退化**成普通列表 | 任务项命中该分支时**不剔除**段落、改填非空锚点；锚点收敛到常量 `TASK_ITEM_ANCHOR` |
| #290 | #292 | 脚本 | 同步 #286 落地后的两处导航性注释契约 |

### 6.1 #268：字面 `<br />` 的根因不在转换器

`list_item` 的 schema 是 `paragraph block*`——列表项**必须以段落开头**。「首块是子列表」的列表项（中间态 `- - a` / `- 3. a`）解析后必然带一个 schema 补出来的空段落，而 Milkdown 的 paragraph 序列化器把「非文档末尾的空段落」写成字面 `<br />`（`remark-preserve-empty-line` 行为），于是该占位段落落进用户的 Markdown 源文件，且插入的空行让该列表项重开后变成松散项（`list_item.spread` false → true）。

**实测 issue 建议的方向（改用 `- \n  - a` 换行形式）无效**：`- - a` 与 `-\n  - a` 解析结果完全相同——空段落来自 schema，任何 Markdown 形态都躲不掉，**只能修序列化侧**。

修法：新增 `markdown-serialize.ts` 的 `stripListPlaceholderParagraphs`，在写盘前剔除「空段落 + 是 `list_item` 首个子节点 + **该列表项后面还有块**」的结构占位段落。第三个判据不可省：唯一子节点是空段落时那是空列表项的内容，剔除会让 `mdast-util-to-markdown` 抛错。没有该段落时返回**同一个 doc 实例**，零重建开销；转换器输出保持不变。

### 6.2 #272：空列表项要保留段落、只换内容

空列表项（裸标记 `-`）的唯一子节点同样是 schema 补出来的空段落。但 #268 的「剔除」不能覆盖这一形态：删掉唯一段落会让 mdast 的 `listItem` 变成没有 `children` 字段的空节点，`mdast-util-gfm-task-list-item` 的 `node.children[0]` 直接抛 `Cannot read properties of undefined`（实测）。

改为「保留段落、换掉段落内容」：给段落塞一个**空值** `html` 锚点（`value: ""`），它在 mdast 里序列化成零长度——段落渲染为空、列表项只剩裸标记。函数随之扩成 `normalizeListPlaceholders`（同时处理 #268 的占位段落剔除与 #272 的空列表项锚定），仍保留「无需改动时原样返回同一个 doc 实例」的快路径。

**注意**：整表都是空 `li` 的 HTML（如 `<ul><li></li></ul>`）转换出的 `-` 会被 `parsePastedMarkdown` 的「解析结果无内容则丢弃」守卫挡下、粘贴为空操作，所以单测 / E2E 用「夹杂空项」的列表复现；保存路径的修复与空项来源无关。

### 6.3 任务项两条修正（#284 / #286）

任务项是这一族里最脆的形态，连续两次修错方向：

- **#284**：任务项此前沿用 #272 的**空值**锚点，而 mdast 侧任务项靠 `value.replace(/^(?:[*+-]|\d+\.)([\r\n]| {1,3})/, …)` 把 `[ ] ` 插到裸标记**之后**——空值锚点让列表项只剩裸标记 `*`，正则匹配不上 → **checkbox 整块丢失**（比保留 `<br />` 更糟）。改用**非空**锚点后列表项值为 `* <!-- -->` → 正则命中 → 输出 `* [ ] <!-- -->`。普通（非任务）空列表项继续用空值锚点。
- **#286**：空任务项（首部空段落 + 子列表）命中 #268 的剔除规则，剔除后 mdast 的 `listItem.children[0]` 变成子列表，而 `mdast-util-gfm-task-list-item` 的 `checkable` 判据要求 `head.type === "paragraph"` → 不输出 `[ ] ` 前缀，勾选项**永久退化**成普通列表（实测 `* [ ] <br />\n  * 子项` → `* * 子项`）。改为任务项命中该分支时**不剔除**段落、改填非空锚点（段落保留 → 标记有处依附），非任务项维持 #268 的剔除规则。

单测用真实 Milkdown parse/serialize 构造该编辑态，覆盖未勾选 / 已勾选 / 有序任务项 + 子列表，并断言「重新解析后仍是勾选项」——不仅是文本形态。

## 7. Benchmark 判定：假 FAIL 根治（#270 / #274 / #285 / #291 / #294）

### 7.1 问题形态

「同一场景首轮 + 复测都超阈值 → FAIL」这条防线（#234 拆出独立 runner 的 retest job）有一个盲区：**两个会话可以同时被拖慢**。共享 runner 池内的并发来源是**跨工作流**的（自家 Build 的 test job、main 打包、其他 Benchmark），workflow 级串行管不到；同一测量窗口里两台 VM 一起变慢时 R1∧R2 双超成立，结论却是错的。2026-09-30 一天三例（main 与两个 PR），换 runner 静默复跑全部证伪。

### 7.2 分层修复

| 层 | issue / PR | 内容 |
|---|---|---|
| 判定口径 | #270 / #271 | ①派生指标的**佐证**改用终判证据基础（见 7.3）；②新增 `effectiveAbsMin = max(登记常数, 1.5×历史极差)`——只对小基数（参考值 <10）计数指标生效、只收紧不放松；③参考值 `max(全历史中位数, 最近 4 点中位数)` |

### 7.3 #270：佐证口径与参考值方向

- **佐证**：此前 `report.mjs` 只看首轮（`primaryOver`），且是**场景级**豁免，而终判用「首轮 + 复测」两轮证据。于是「首轮超、复测回落」已被判 WARN / 已宣告是抖动的主指标行，仍能给全场景的派生指标发豁免券 → 出现「零主指标 FAIL 的场景产出 FAIL、exit 1」。改为 `primaryReproduced = 本场景存在同样被判 FAIL 的主指标`。check 阶段的复测筛选**仍按首轮**（那时只有首轮数据，且其语义只是「值不值得再跑一轮」，不参与结论）。
- **地板**：`longFrameCount` 这类指标参考值只有个位数，百分比规则把小差异放大到 400%+，而登记地板 3 与它自身的跨运行极差 3 同量级 → 门槛贴着噪声走。新增由同一份代码历史散布推导的地板，报告单独列出被抬高的行。
- **参考值方向**：只跟随「环境变慢」**上抬**；反方向（近况偏低时下压）实测会让 quick 档 46 行参考值下降（最多 −50%）、仅 2 行上抬，等于把判定系统性推向偏严——本轮就曾把 `frameMs.p95` 从 WARN 翻成 FAIL。故**刻意不做**下压；要让「环境变快」也安全反映到参考值上，前提是标定归一化（独立议题）。

验证方式：用 run `36410892157` 的真实产物回放 `report.mjs --phase=final`。改造前 FAIL 1 / exit 1 / `longFrameCount=FAIL`；改造后 FAIL 0 / exit 0，`longFrameCount` 落成 WARN「变化低于该指标的绝对地板」、`jankCount` 落成 WARN「派生指标无主指标佐证（疑似运行抖动）」。

### 7.4 #291：Benchmark 全局串行化

```yaml
concurrency:
  group: benchmark          # 静态名（不含 ref）→ 跨 PR / main / tag 全局串行
  queue: max                # 最多 100 个 pending，FIFO，排队中的运行不被顶掉
  cancel-in-progress: false # 排队而不取消：发版验证与播种绝不丢失
```

边界如实披露（官方语义）：队列满（100）时**新入队者**被取消；FIFO 以「开始等待的时刻」排序，不保证严格顺序；`queue: max` 与 `cancel-in-progress: true` 互斥。重要运行（tag / 播种）仍建议在安静窗口触发。CONTRIBUTING 的播种纪律说明同步改为「由流水线强制」。

### 7.5 #294：第三个 runner 确认

**根治口径**：FAIL 必须由第三个独立 runner 上的会话确认，且确认轮自身不可信时不允许产出 FAIL。

- **`judgment.confirmVerdict(overRounds)`**：参与判定的**每一轮**都超才确认，末轮回落即降 WARN。取「末轮仍超」而非「多数 ≥2/3」——3 例假 FAIL 的核验轮**全部回落**，2/3 会把其中 2 例继续判 FAIL。
- **`report.mjs` 新增 `--phase=confirm`**：产出 `retest2.json`，退出码恒 0（与 check 同性质：**不构成结论**）；三轮终判、`UNCONFIRMED` 集合、标定越界处置、表格「复测2」列与「判定轮次」披露行。
- **#270 的主指标佐证基准同步扩到三轮**：主指标必须每轮都超才给派生指标豁免券，否则「末轮已回落」的主指标仍会发券，在三段路径上重演 #270。
- **绝对行同样纳入三轮**：`frameMs.p95(绝对)` / `jankRatePct(绝对)` 此前也是「双超即判 FAIL」，只改相对行会让它成为假 FAIL 的漏网口。
- **标定越界（`probeMs > 基线历史上限 × 1.1`）只决定「要不要再验一轮」，不作 FAIL 抑制门禁**：实测它既非必要也非充分（范围内照样出假 FAIL、高偏差的核验会话照样正常），拿它抑制会连真回归一起放过。复测轮越界 → 该场景并入确认轮候选；确认轮越界 → 不确认 FAIL，落 `UNCONFIRMED`。
- **退出码**（沿用「更根本的结论优先」）：`UNMEASURED` → exit 2；否则 `UNCONFIRMED` 且 `PERF_REQUIRE_COMPARISON=1` → exit 2；否则有确认 FAIL → exit 1；否则 exit 0。**确认轮整轮没测到（有候选但零采样）属链路故障，PR 与 tag 一律 exit 2**——它不是「结论不完整」，若按 UNCONFIRMED 让 PR 走 exit 0，读者会误以为「复测回落了」。
- **编排**（决策仍是纯函数，有单测锁语义）：
  - `retest-plan.planConfirmPhases({splitRetest, candidates}) → handoff | finalize`。本地单进程**不采纳 handoff**——没有下一个 job，硬移交等于「有候选但不判结论」；
  - `benchmark.mjs` 新增 `PERF_RETEST2_ONLY`（确认轮 job）与 `PERF_FORCE_SUSPECTS2`（确定性演练钩子），并**按运行模式区分目录清空**：只清本轮会写的目录，上游产物（`raw` / `raw-retest` / `retest2.json` / 基线）**一个都不能动**——清错会把三轮 final 退化成两轮；
  - `benchmark.yml` 新增 `retest2` job（`needs: retest`，`if suspects2 == 'true'`）与 `force_suspects2` 输入。不加 job 级 `concurrency`——workflow 级 `queue: max` 已串行整条流水线。

### 7.6 补上真正的测试缺口

编排层（`benchmark.mjs` 的 splitRetest / 清空矩阵）在此前**没有任何入库回归测试**——PR 自称的「编排端到端 30 条断言」是外部回放。首版评审的 **P0**（CI `retest` job 漏传 `PERF_SPLIT_RETEST=1`，导致确认轮永不移交、第三轮退化成与 R2 同 runner，**tag 发版验证以假 FAIL 收尾**——正是 #294 要根治的形态）就是从这里漏出去的：**纯函数测试锁不住「调用方有没有传对参数」**。

修复：新增 `tests/unit/perf-orchestration.test.ts`（17 例）——9 例**直接读 `benchmark.yml`** 断言每个 job 的 `env` / `needs` / `if` / `outputs`，8 例用桩 Playwright 端到端真跑 `measure → retest → retest2` 三个 job，断言上游产物不被误删、假 FAIL 被拦、真回归仍 FAIL。凡「工作流 / 配置 → 代码」的关键 wiring，都必须有一条直接读配置的测试。

CONTRIBUTING 新增「**发版负责人核对清单**」：`判定覆盖 N/M` 必须相等（N ≠ M 就是「没比出结论」）、`判定轮次` 要走到 `首轮 ✓ 复测 ✓ 确认 ✓`（出现 `UNCONFIRMED` 要换 runner 重跑，**不要**按「没回归」放行）、`FAIL` 计数与成因（被噪声 3σ 或绝对地板挡下的**不是**回归）。

## 10. 已知边界与未决项

- **真机 DOM 渲染耗时**：粘贴路径的端到端体感（大段 HTML 粘贴后的首屏渲染）无有效自动化量化手段，属人工核对项，不宣称「已验证达标」。
- **`sanitizeHTML` 两个模式的规则差异**是刻意的（`paste` 模式丢弃危险标签内容、渲染模式保留既有行为），但两份白名单同处一文件、靠 `mode` 分支——将来扩白名单时需同时确认两模式语义。
- **私有区字符**：占位区固定为 U+E000–U+E006，区间外的私有区字符不受影响；若将来需要更多占位符，必须同步扩 `encodeSentinels` 的 `SENTINEL_RE`。
- **`MAX_MARKDOWN_PASTE_CHARS` = 64K 是经验上界**：基于 dev 构建实测（最坏情况 64K ≈1.7s），未在 release 构建上重测；超限后仍会走 ProseMirror 默认纯文本粘贴（数万短行段落本身有既有成本）。
- **远程图片**：不发送 `Referer` 会让防盗链站点返回 403（这是**设计取舍**，已在提示文案里说明）；单图 10MB / 单次 30 张 / 15s 超时都是硬上限，超出保留远程引用而非失败。
- **Benchmark 标定越界不是可靠信号**（实测既非必要也非充分），本版只是明确它「不作 FAIL 抑制门禁」。真正要让「环境变快」也安全反映到参考值上，前提是**标定归一化**——独立议题，未在本版解决。
- **`queue: max` 的 FIFO 不保证严格顺序**，且队列满（100）时新入队者被取消；重要运行仍建议在安静窗口触发。
