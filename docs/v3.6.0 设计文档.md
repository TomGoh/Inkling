# v3.6.0 设计文档 —— 链接跟随（Link Following）

> 版本：v3.6.0（2026-10-21）
> 范围：自 v3.5.0 起 **18 个提交（含 6 个 merge，合并 6 个 PR）/ 70 个文件（+3523 / −841，不含本版发版文档提交）**。
> 主线：把「点链接」这一件小事做完整——统一判定、动作分派、锚点匹配、相对路径打开、WebView 导航兜底，以及能真正拦住回归的测试防线。

---

## 1. 背景与目标

v3.5.0 之前，链接跟随只有一条按「修饰键 + 三类 href 白名单」硬编码的判定：`Ctrl/Cmd + 点击` 能打开 http 外链与应用内锚点，其余情况要么静默无反应，要么更糟——原始 HTML 块里的 `<a>` 裸点一下会把整个 WebView 导航走，而 Rust 侧没有任何兜底。

本版要解决的不是一个 bug，而是四条互相纠缠的缺陷：

| 用户看到的现象 | 根因 |
|---|---|
| 点 `[文档](notes/a.md)` 没反应 | 相对路径没有解析与打开通路 |
| 从 GitHub 拷来的 `#hello-world-1` 找不到标题 | 匹配端用一套 slug，标题 DOM id 用另一套，且不解析重复标题序号 |
| 点原始 HTML 里的链接，应用被导航到 `tauri://localhost/xxx/README.md` | html 块不在 ProseMirror 的 link mark 通路上，且 WebView 没有导航白名单 |
| 链接相关的 E2E 看起来全绿，但改坏逻辑也不红 | 断言恒真（`typeof after === "number"`）、基线被 `void` 丢弃 |

目标：

1. **该跳的能跳**：工作区内相对路径、带锚点的文件链接、应用内锚点、原始 HTML 内的相对链接；
2. **不该跳的绝不跳**：裸点击 / 中键只阻断默认行为，任何 `<a>` 都不能把应用导航走；
3. **错的地方有反馈**：目标不存在、越出工作区、非 Markdown、`file://` 都有非阻塞提示；
4. **回归能被抓住**：每条修复都配可被变异打红的用例。

非目标：不做双链 / 反向链接；不做 `{#custom-id}` 自定义锚点语法；不把裸点击改成「跟随链接」；不用外部程序打开 `file://` 本地文件。

## 2. 用户能感知到的变化

- **相对路径真的能打开了**：`[周报](weekly/2026-10.md)`、`[上一级](../index.md)`、`[带锚点](notes/a.md#小结)` 都会在工作区打开目标；目标已在标签页里则直接切过去。
- **锚点兼容外部文档**：中文标题、含标点标题、重复标题的 `-1`、URL 编码锚点、Milkdown 自己生成的 `-#2` 都能命中；写错的锚点保持静默，不弹提示。
- **自链接不重开**：在 `a.md` 里点 `a.md#小节` 只滚动当前文档；分屏里点自链接只滚分屏，不会把主面板的标签抢走。
- **误点不再毁掉应用**：裸点击 / 中键只阻断浏览器默认行为；即使脚本主动 `location.href = ...`，Rust 白名单也会拦下。
- **失败有提示**：`无法打开：文件不存在`、`链接目标不在工作区内`、`仅支持打开 Markdown 文件`、`不支持 file:// 链接`，4 秒自动消失，不打断编辑。
- **原始 HTML 里的相对链接也能跟随**：`<a href="readme.md">` 从「渲染时被丢弃」变成「保留并可 Ctrl+点击」，但 `img src` / `use xlink:href` 的相对值仍然拒绝。
- **Windows 路径大小写不再误判**：根目录 `C:\Work\Notes` 与链接 `c:\work\notes\a.md` 视为同一棵树；纯 POSIX 路径仍大小写敏感。

## 3. 总体方案

### 3.1 一次点击的处理链

```
鼠标按下/点击 <a>
  → capture 阶段统一入口（view.dom）
  → 立刻 preventDefault()            // 不变量：应用内永不发生浏览器默认导航
  → classifyLink(href, { documentPath, workspaceRoot })   // 纯函数，5 kind / 6 reason
  → performLinkAction(cls, deps)     // 纯分派，依赖全部注入
      ├─ external       → 系统浏览器（桌面）/ window.open（浏览器）
      ├─ anchor         → 文档内滚动
      ├─ workspace-file → 自链接滚动 / 先登记 pending 再 openFile / 失败撤销并提示
      ├─ unsupported    → 固定文案提示
      └─ empty          → 无动作
```

这条链的关键是「判定」与「执行」分离：判定是纯函数，可以表驱动单测与变异；执行只做副作用，依赖注入后不需要挂载 Tauri 或真实浏览器也能测。

### 3.2 分类器（`src/lib/link-target.ts`）

输出 5 种 kind：

| kind | 触发条件 | 动作 |
|---|---|---|
| `empty` | href 为空 | 无 |
| `anchor` | `#frag` | 文档内滚动，未命中静默 |
| `external` | `http(s)` / `mailto` / `tel` 等白名单协议 | 交给系统浏览器 |
| `workspace-file` | 相对路径 / 绝对路径，且落在工作区内、扩展名为 `.md` | 打开文件 |
| `unsupported` | 其余 | 按 reason 提示 |

6 种 reason：`local-file`（`file://`）、`blocked-scheme`（未知协议）、`outside-workspace`（越界）、`not-markdown`（非 md）、`no-workspace`（草稿无法解析相对路径）、`no-workspace-root`（未打开工作区）。

判定顺序里有一条必须写死的规则：**先判绝对路径，再判 scheme**。否则 `C:\notes\a.md` 会被当成 `c:` 协议。

### 3.3 锚点表（`src/lib/heading-anchors.ts`）

不再「每次点击遍历文档找第一个 slug 相等」，而是先把标题构建成一张纯数据表：

```ts
{ index, level, text, baseSlug, domId, occurrence }
```

`occurrence` 是同一 `baseSlug` 的第几次出现（0-based，层级变化不重置，与 GitHub 一致）。匹配按固定优先级：

1. **原始 slug**（忽略大小写）；
2. **精确 DOM id**；
3. **宽容 slug**：`slugify(fragment)` 后再比；
4. **GitHub 序号**：`x-1` → 第 2 处；
5. **Milkdown 序号**：`x-#2` → 第 2 处。

顺序是语义的一部分：

- 第 2 步必须早于第 3 步：`foo-#2` 会被 `slugify` 成 `foo-2`，如果文档里同时有标题 `Foo 2`，宽容分支会把重复标题的真实 id 抢走；
- 第 1/3 步必须早于第 4/5 步：标题 `Step 1` 的 slug 是 `step-1`，否则会被解析成「`step` 的第 1 个重复」；
- 第 4/5 步的 base 必须过 `slugify`：否则 `#Hello, World!-1` 这种 GitHub 原形不命中；
- 序号必须**严格存在且 ≥1、无前导零**：只有 2 处 `x` 时，`#x-9` / `#x-0` / `#x-01` 都返回 `null`（GitHub 与 Milkdown 都不生成这些 id）。

另一个事实修正：Milkdown 的 `syncHeadingIdPlugin` 去重计数是 **1-based**，第 2 处是 `-#2` 而不是 `-#1`。本版同时支持真实 id（精确命中）与文档里的 `-#1` 兼容别名。

### 3.4 pending 锚点（`src/lib/pending-anchor.ts`）

「打开文件 → 滚到锚点」跨两个生命周期：点击发生在插件回调里，目标编辑器可能尚未挂载。因此用一张模块级登记表：

- 键是 `pathKey`（`normalizePath` + Windows 大小写折叠），链接解析路径与 tab 路径仅大小写不同也能命中；
- 同一路径只保留最近 1 条，消费即删；
- 容量上限 8 条，超出淘汰最早，避免打开失败时无限堆积；
- 打开失败会撤销登记，防止日后误消费。

消费端在编辑器就绪后执行。这里有一个实测踩到的时序：`useCursorStateRestore` 在挂载时会「立即 + 逐帧」把 `scrollTop` 写回 0（新文件没有记忆值），同步滚动会被它随后一帧覆盖。因此消费端延后两帧再滚，等它的 settle 循环停下。

### 3.5 导航守卫（`src-tauri/src/navigation_guard.rs`）

Tauri 插件级 `on_navigation`：任何 webview 只允许留在应用自身 origin（`tauri://localhost` / `http://tauri.localhost` / dev `http://localhost:1420`）与 `asset:` 协议，其余一律拒绝。

它不是「替代前端 preventDefault」，而是第二道防线：前端捕获层负责让正常点击不触发默认行为，Rust 负责即使前端漏了、或页面脚本主动跳转，应用也不会离开自己的 origin。

### 3.6 原始 HTML 内的相对链接（`html-view.ts`）

渲染模式此前对无协议相对 href 一律丢弃（安全考虑）。本版只开一个窄口径：

```ts
const allowRelative = paste || (lowerTag === "a" && lowerName === "href");
```

只对 `<a href>` 放行相对值；`src` / `xlink:href` 仍拒绝，避免 `<img src="../../secret">` 或 `<use xlink:href>` 扩大资源读取面。`javascript:` / `data:`（非图片）/ `file:` / `vbscript:` / `C:\...` 继续拒绝。

## 4. 关键决策与取舍

| 决策 | 选择 | 理由 |
|---|---|---|
| slug 的唯一真值源 | 覆写 `headingIdGenerator` 为应用 `slugify`，匹配端宽容接受多形态 | 生成端与匹配端天然一致；对外部文档的锚点保持宽容 |
| 裸点击语义 | 维持「不跟随」 | 编辑时点链接主要是定位光标，跟随属产品语义变更，另立项 |
| 相对路径边界 | 以当前文档目录为基准，禁止越出工作区 | 与图片解析一致；越界给提示而不是静默 |
| 非 md 目标 | 不打开 + 非阻塞提示 | 与文件树对非 md 的禁用语义一致 |
| 打开失败原因 | 优先取 store 的 `fileOpenErrors`，退回异常 message | 后端错误（编码 / 过大 / 不存在）对用户更有用 |
| 存在性检查 | 只由 `openFile` 的失败承担 | 不做「先 stat 再打开」的双次 IO |

## 7. 已知边界与未决项

1. **源码模式没有标题 DOM**：`x.md#frag` 会打开文件但不滚动；按设计属已知边界，不在本版解决。
2. **原始 HTML 内的绝对 Windows 路径**（`<a href="C:\ws\x.md">`）仍被协议白名单拒绝；本版只放行无协议相对值。
3. **重复标题的导出 id 是 `-#2`（1-based）**，与 GitHub 的 `-1` 不同；应用内两种形态都能匹配，导出物在应用外使用时应以 `-#2` 为准。
4. **桌面真机只覆盖 Windows / WebView2**；macOS WKWebView 行为未自动化，发版说明中保留为未覆盖项。
5. **每次点击现构建锚点表**：标题数量在编辑器尺度下很小，O(标题数) 远低于一次点击预算；缓存会引入失效同步问题，暂不引入。
6. **不支持 `{#custom-id}` 自定义锚点语法**；也暂不支持 HTML 内的 `target` / `download` 特殊语义，按普通链接处理。
