# InklingMD v2.7.1 设计文档

> **版本**：v2.7.1
> **日期**：2026-08-28
> **关联 Issue**：[#136](https://github.com/zhkp/InklingMD/issues/136)（模式切换后滚动位置与光标丢失）
> **前置**：v2.6.3（#117 RAF 多帧布局沉降）、v2.7.0（#121 比例映射还原）

---

## 1. 背景与问题

上游 #136 报告：在长文档中于富文本模式滚动到非顶部位置后切换到源码模式，或反之，滚动位置回到顶部 / 与预期映射位置偏差大，且光标不可见，需要手动滚动很远才能找回编辑位置。

### 1.1 独立验证结论（不完全采信 issue 分析）

复现并逐层定位后，确认实际存在 **四个相互叠加的缺陷**，与 issue 的归因部分重合、部分不同：

| # | 缺陷 | 方向 | 根因 | issue 是否提及 |
|---|---|---|---|---|
| D1 | 双写者竞争 | 退出（源码→富文本） | `useSourceModeTransition` 的恢复 effect 与 tab 记忆恢复 effect 在同一提交内先后写同一 `scrollTop`，后者用被污染的旧值覆盖前者 | 部分（归因为"恢复链路缺失"，实际是"恢复链路有两个互不知情的写者"） |
| D2 | tab 记忆污染 | 进入（富文本→源码） | 进入源码模式瞬间富文本容器 `display:none` 塌缩，`scroll` 监听把 `scrollTop=0` 防抖写入 tab 记忆，此后一切恢复读到 0 | 部分 |
| D3 | 高度估算覆盖 | 进入 | CodeMirror 首帧 `scrollHeight` 为估算值且逐帧修正，单次 `scrollTop` 赋值被 clamp 到错误上限 | 是（"CM 高度估算"） |
| D4 | 映射系统性欠滚 | 退出 | `mapScrollTop` 以「视口顶部」为基准：`scrollTop/scrollHeight` 在文档底部恒小于 1，映射目标必然落在真实底部上方，光标所在行滑出折叠线下方 | **否**（issue 未发现；这是光标不可见的可靠复现根因） |

### 1.2 关键证据

- 退出方向实测：CM `scrollTop=23974/24583` → 映射目标 54371，而光标锚点段落位于视口相对 y≈1449（视口高 720），即 `ratio>0.5` 断言可通过但光标位于折叠线下方 729px——**仅断言滚动比例不足以证明恢复正确**。
- Milkdown 下 PM 内部认定的滚动容器与 `.editor-scroll` 不一致，`tr.scrollIntoView()` 的滚动不作用于实际容器，不能作为光标可见性兜底。

## 2. 方案设计

### 2.1 单一写者原则（治 D1/D2）

- 抽取 `useCursorStateRestore`：承接原 tab 恢复 effect 的职责（tab 切换 / 初次加载恢复光标与滚动）。
- 用 `prevSourceModeRef` 检测模式翻转帧，翻转帧**显式跳过恢复**，把该帧的写权完全让给 `useSourceModeTransition`；同时退出恢复完成后由 transition 把实际位置写回 `saveCursorState`（单一事实源），此后 tab 切走再切回读到的都是模式切换结束时的真实位置，D2 的污染值被覆盖淘汰。

### 2.2 源码进入 settle 循环（治 D3）

`SourceModeEditor` 挂载后：立即应用初始 `scrollTop`，随后最多 30 帧 rAF 逐帧检查 `|scrollTop − target|`，未收敛则重设。CM 高度估算逐帧收敛后 clamp 上限逐步放开，循环最终稳定在映射目标或 30 帧超时退出（防死循环）。

### 2.3 光标可见性最小校正（治 D4）

transition 的退出恢复收敛后：

1. `view.coordsAtPos(selection.head)` 取选区视口坐标；
2. 统一坐标系（#138 review）：`.editor-scroll` 在 `editorZoom != 100%` 时带 CSS `zoom`，`coordsAtPos`/`getBoundingClientRect` 返回缩放后视口坐标而 `scrollTop`/`clientHeight` 为布局单位；`getScrollZoom` 读取有效 zoom（computed zoom 优先，`rect.height/clientHeight` 几何推断兜底），光标相对容器顶边的视口偏移 `÷ zoom + scrollTop` 换算为内容布局坐标；
3. 与 `[scrollTop, scrollTop+clientHeight]` 比较，超出时仅做**最小滚动**（上方越界 → 顶部对齐，下方越界 → 底部对齐，margin 8px），已可见则完全不动，保持比例映射锚点不被破坏；
4. 校正后的实际 `scrollTop` 写回 tab 记忆。

### 2.4 时序总览

```
进入源码模式：
  unmount(PM) → SourceModeEditor mount
    ├─ frame0: 注册 scroll 监听、初始 scrollTop 立即应用
    └─ frame1..30: settle 循环逐帧重设直至收敛（D3）

退出源码模式：
  unmount(CM)（onUnmountSnapshot 记录 cursor/scrollTop/scrollHeight）
    → layout effect: transition 恢复（唯一写者，D1）
        ├─ replaceWith(新文档) + setSelection(映射光标)
        ├─ scrollTop = mapScrollTop(...) + settle 循环（同 2.2）
        ├─ 收敛后 coordsAtPos 最小校正（D4）
        └─ saveCursorState(实际值) 写回 tab 记忆（D2 淘汰污染值）
```

## 4. 测试方案

- **单元**
  - `useCursorStateRestore.test.ts`：true→false / false→true 翻转跳过；filePath 变化正常恢复；无记忆显式归零。
  - `source-mode-editor-initial-scroll.test.tsx`：stub `scrollTop` setter 模拟 CM 高度逐帧增长（100→300→800），断言逐帧收敛至映射目标 500。
  - `useSourceModeTransition.test.ts`：断言退出恢复后实际 `scrollTop` 写回 `saveCursorState`；zoom=1.25 缩放用例锁定坐标系换算（视口偏移 ÷ zoom + scrollTop）。
- **E2E（`source-mode-scroll.spec.ts`）**
  - A：源码模式底部编辑 → 退出：`ratio > 0.5` 且编辑锚点 `toBeInViewport`；
  - A2：进入前富文本已滚动到中部（构造 tab 记忆 ≠ 0 的竞态路径）→ 退出仍以源码侧结束位置为准（单一写者回归锁）；
  - B：富文本底部 → 进入源码：`ratio > 0.5` 且标题行 `toBeInViewport`（CM 视口化渲染：不可见即不渲染，断言天然可靠）。
- 全套 81 个单测文件（525 用例）、157 个 E2E、`tsc --noEmit` 100% PASS。

## 5. 风险与取舍

- 30 帧超时兜底保证 settle 循环不会因极端布局抖动死循环。
- 最小校正在"光标远离映射视口"场景（进入前滚走、光标留在原处）会以光标可见优先，偏离比例锚点——与 issue 的核心诉求（找回编辑位置）一致。
- `coordsAtPos` 在 PM 未完成排版时可能抛错，包裹 try/catch 静默降级为纯比例映射。
