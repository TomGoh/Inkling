# v2.5.2 设计与缺陷修复文档

## 1. 背景与目标
在针对 `v2.3.8` ~ `v2.5.1` 的深度 Code Review 审查中，识别出了部分高优先级安全与状态并发缺陷、潜在风险及测试有效性问题。`v2.5.2` 重点聚焦安全防线加固、多标签与保存状态最小 Patch 保护、生命周期 Flush 闭环及测试套件真实性改造。

## 2. 详细设计与实现

### 2.1 Mermaid SVG 深度清洗与 XSS 纵深防御 (H1)
- **风险**：HTML 规范在解析 URL 前会自动剥离 `\t`、`\n`、`\r` 等空白控制字符，若仅以字面量匹配 `javascript:`，可能被 `jav&#x09;ascript:` 等编码绕过；且黑名单漏防 `vbscript:`、非图片 `data:` 伪协议及 `<iframe/embed/object/form/base>` 嵌套。
- **方案**：
  - 在 `mermaid-view.ts` 内构建 `sanitizeMermaidSvg`，针对所有属性值执行控制字符剥离：`attr.value.replace(/[\t\n\r]/g, "").trim().toLowerCase()`。
  - 严格拦截以 `on` 开头的事件属性、`javascript:`、`vbscript:`、`data:(?!image/)` 以及 `expression(` 样式。
  - 递归移除 `<script>`、`<iframe>`、`<embed>`、`<object>`、`<form>`、`<base>` 等高危标签。

### 2.2 保存异步窗口最小 Patch 保护 (H2)
- **风险**：`saveCurrent` 在读取磁盘和弹窗等待确认期间，分屏防抖或输入事件可能更新 `openTabs`。若保存完成后用进入函数时的旧快照整体覆盖 `openTabs`，会导致异步窗口内的最新编辑被静默回退。
- **方案**：
  - 在保存成功后重新调用 `get()` 获取最新 store 状态。
  - 使用最小 patch 机制，仅更新目标 tab 的 `dirty: false`、`savedContent`、`diskContent` 与 `revision`，杜绝覆盖其他标签页或当前标签页在弹窗期间的新输入。

### 2.3 窗口卸载与应用生命周期 Flush (H3)
- **方案**：
  - 在 `App.tsx` 注册 `window.beforeunload` 监听器，在窗口关闭/刷新时同步触发 `flushAllMarkdownPublishers()`。
  - 暴露 `hasPendingMarkdownPublishers()` 查询状态。

### 2.4 Store 层 Tab 契约补齐 (M1/M2)
- **方案**：
  - 将 Flush 责任完全下沉至 store 层：`switchTab`、`closeTab`、`closeOthers`、`closeToRight`、`closeAll`、`newTab`、`splitSwap` 在入口统一执行 `flushAllMarkdownPublishers()`。

### 2.5 源码模式 Mermaid 预渲染性能优化 (M3)
- **方案**：
  - 在 `mermaid-view.ts` 的空闲预渲染任务中增加 `container.offsetParent === null` 判定。当处于源码模式（容器隐藏）时直接跳过渲染，避免无意义的 CPU 浪费与高度 0 缓存污染。

### 2.6 真实测试用例重构 (M4)
- **重构内容**：
  - `MermaidSanitize.test.ts`：补充 `\t` 控制字符绕过、`vbscript:`、非图片 `data:` 及 SVG 元素 `namespaceURI` 验证。
  - `imageSrcCache.test.ts`：以真实的 Tauri 模拟环境验证图片 LRU 淘汰与缓存命中顺序更新。
  - `workspace-reload-tab.test.ts`：真实调用 `reloadFile` 验证当前 Tab 与后台 Tab 的 `revision` 递增与内容同步。
  - `MermaidPerf.test.ts`：移除自测型伪测试，接入真实的 `renderMermaidWithSeq` 异步竞争中断校验。
