# InklingMD v2.8.1 设计文档

> **版本**：v2.8.1
> **日期**：2026-08-30
> **类型**：Bugfix（自身自动保存写盘被文件监听误判为外部修改）
> **关联 Issue**：Fixes #144
> **前序版本**：v2.8.0

---

## 1. 背景与根因

桌面端编辑（源码模式高频输入时尤甚）会随机弹出「文件已被外部修改」提示或 ConflictDialog，但文件实际未被任何外部程序改动——Diff 两边内容几乎一致，confirm 后重载内容无变化。

### 1.1 触发路径

1. 打开已有 `.md` 文件（桌面端 Tauri 环境）
2. 切到源码模式连续输入后停顿（触发 2 秒防抖自动保存，静默写盘）
3. 等待 3~6 秒（越过保存忽略窗的下一次轮询）
4. 弹出「文件已被外部修改」或 ConflictDialog

### 1.2 三处结构性缺陷叠加

| # | 缺陷 | 位置 |
|---|---|---|
| 1 | **保存忽略窗只推迟检查、从不刷新基线** | `useFileWatcher.ts` L136-140：保存后仅设置 `ignoreUntil = now + 2000`（跳过检查），`knownMtimesRef` 里的旧 mtime 从不更新 |
| 2 | **watcher 与 store 的 mtime 记录互不通信** | `tabs.ts` L732-734 已把写盘后读回的 `savedMtime` 存进 `tab.diskMtime`，但 watcher 的 store 订阅未消费该值 |
| 3 | **时序上弹窗必然出现在保存后 3~6 秒** | 写盘已改变磁盘 mtime，2 秒窗一过，3 秒轮询（`POLL_INTERVAL=3000`）必然对比出新旧差异 → 误报 |

另注：`SAVE_IGNORE_WINDOW=2000` 与自动保存防抖 `BASE_AUTOSAVE_DEBOUNCE_MS=2000` 数值巧合相同，连续编辑时忽略窗可能与下一次自动保存几乎同时到期，进一步放大误报概率。

---

## 2. 核心方案：三道防线

修复集中在 `src/lib/useFileWatcher.ts`，三道防线由主到辅覆盖不同竞态时序。

### 防线 A（主修）：保存事件登记基线

**位置**：store 订阅中，保存事件触发时。

```typescript
// 原有逻辑：仅设忽略窗
ignoreUntilRef.current = Date.now() + SAVE_IGNORE_WINDOW;

// 新增：把写盘后的 tab.diskMtime 主动登记为 watcher 新基线
for (const tab of s.openTabs) {
  if (tab.lastSavedAt === s.lastSavedAt && tab.diskMtime !== undefined) {
    knownMtimesRef.current.set(tab.path, tab.diskMtime);
  }
}
```

**匹配条件**：`tab.lastSavedAt === s.lastSavedAt` 在 `saveCurrent` 中两者均为同一 `now`，成立。

**覆盖场景**：前台 tab 自动保存（最常见路径）。

### 防线 B（兜底）：diskMtime 容差基线

**位置**：轮询 check 内，mtime 变化检测之后。

```typescript
// 新增：mtime 变了，但与 store 记录的写盘基线一致 → 自家写盘，静默登记
if (tab.diskMtime !== undefined && Math.abs(mtime - tab.diskMtime) < MTIME_TOLERANCE_MS) {
  knownMtimesRef.current.set(filePath, mtime);
  continue;
}
```

**覆盖场景**：后台 tab 自动保存（此时 store 级 `lastSavedAt` 仅在 `activeTabPath` 匹配时更新，A 不触发）。

### 防线 C（语义修正）：忽略窗内刷新基线但不弹窗

**原逻辑**：`if (Date.now() < ignoreUntilRef.current) return;` —— 整个检查跳过。

**新逻辑**：
- 忽略窗内轮询**继续执行**（保留 IO + 删除检测），
- mtime 变化时**刷新基线**（消除窗口一过的补弹根因），
- 但**跳过弹窗**（`if (withinSaveIgnoreWindow) continue;`）。

**额外收益**：忽略窗内的 `fileMtime` IO 使真实外部删除的 `deletedOnDisk` 标记不再被整体跳过。

**已知权衡**：若一次真实外部修改恰好落在自家保存后 2 秒窗口内且被窗内轮询捕获，会被静默吸收（旧代码会延迟弹窗）。该场景窗口极窄，且下次保存时 `tabs.ts` 的磁盘内容比对（`latestOnDisk !== tab.diskContent → shouldCheckConflict`）仍会兜住覆盖风险，可接受。

### MTIME_TOLERANCE_MS 常量

将散落的字面量 `5` 提取为具名常量 `MTIME_TOLERANCE_MS = 5`，注释说明文件系统时间戳精度不一致。该容差沿用 `tabs.ts` 保存冲突快速路径的既有口径。
