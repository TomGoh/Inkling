# InklingMD v2.5.3 设计文档

## 1. 背景与目标
针对上一轮 Code Review 反馈（H3 未落盘、H2 入口快照、M4 测试去伪、animate 属性硬化等），进行彻底修复与质量加固，确保数据无损、安全无死角、测试 100% 真实。

## 2. 核心设计与修复方案

### 2.1 窗口退出/关闭事件拦截与落盘保障 (H3)
- **机制**：通过 `@tauri-apps/api/window` 的 `getCurrentWindow().onCloseRequested` 拦截系统原生窗口关闭事件。
- **流程**：
  1. `event.isPreventDefault = true` 阻止瞬时销毁；
  2. 同步执行 `flushAllMarkdownPublishers()` 将 ProseMirror 内存状态发布至 zustand store；
  3. 检查 `useWorkspace.getState().dirty`，若存在未保存内容则 `await saveCurrent()` 真正写回磁盘；
  4. 最终调用 `await win.destroy()` 安全退出。

### 2.2 `saveCurrent` 入口防抖 Flush 契约 (H2)
- 在 `saveCurrent` 执行体的第一行直接调用 `flushAllMarkdownPublishers()`。
- 确保执行入口解构出来的 `currentContent` 永远是最新状态，彻底消除“调用 saveCurrent 前需外部手动 flush”的脆弱隐式契约。

### 2.3 LRU 图片缓存真实测试加固 (M4a)
- 重写 `tests/lib/imageSrcCache.test.ts`。
- 通过为 `resolve` 打桩加入 `calls` 计数器，断言同参二次调用命中缓存且 `calls === 1`。
- 插入 501 个不同 key，断言首个 key 被淘汰且再次调用时 `calls` 递增，全面验证 LRU 顺序与 500 容量淘汰。

### 2.4 消除 Mermaid 渲染孪生函数 (M4b)
- 将 Mermaid 并发渲染与取消令牌检查收敛为 `renderMermaidWithSeq` 核心函数。
- `MermaidNodeView.render()` 与单测 `MermaidPerf.test.ts` 均复用此核心逻辑，杜绝双轨实现漂移。

### 2.5 SMIL `<animate>` 属性名注入硬化 (Hardening)
- 在 `sanitizeMermaidSvg` 属性遍历中，增加对 `<animate>` 标签 `attributeName` 值的检查。
- 若 `attributeName` 包含 `on*`（如 `onload`），立即移除该属性，填补 XSS 纵深防御最后一格。
