## 一、大型工作区按需加载与文件树渲染（issue #11 / PR #15）

### 现象

打开包含大量文件/子目录的工作区时，侧边栏文件树卡顿甚至短暂冻结主线程；深层目录（如 `node_modules`）被无意义枚举，既慢又产生权限噪音。

### 根因

Rust 端 `list_dir` 递归扫描整棵目录树（默认 10 层），同步执行在 Tauri 异步运行时线程上，深层/超大目录会阻塞前端所有 IPC 调用；前端拿到整棵树后一次性渲染全部节点，DOM 数量与目录规模成正比。

### 修复

**Rust 后端**（`src-tauri/src/commands/mod.rs`）：
- `list_dir` 改为只列出目录的**直接子项**（单层浅扫），`max_depth` 参数仅为兼容旧前端保留；文件系统操作迁入 `tauri::async_runtime::spawn_blocking` 线程池，避免阻塞异步运行时。
- 跳过隐藏项（`.` 开头）、常见依赖/构建目录（`node_modules`/`target`/`dist`/`build`/`out`）与目录符号链接；仅返回目录与 Markdown 文件，目录在前并按名称排序（排序键收集时只计算一次，避免比较器反复分配 lowercase 字符串）。

**前端**（`src/components/Sidebar/Sidebar.tsx`、`src/store/workspace.ts`、新增 `src/lib/fileTree.ts`）：
- 目录树**按需逐层加载**：打开工作区只读根目录一层并默认只展开根目录，子目录展开时才调 `list_dir`。
- 大目录**窗口化渲染**（windowing）：只渲染可视区域附近的行，DOM 数量恒定，不随目录规模增长。
- 竞态与去重：同一目录的并发加载只枚举一次；工作区切换时较旧的结果不覆盖后来打开的工作区；连续强制刷新会追赶最新变更；刷新父目录时保留已加载的子树；目录删除/重命名时迁移展开偏好与加载状态。

### 测试

新增 `tests/lib/fileTree.test.ts`（6）、`tests/store/workspace-tree.test.ts`（20）、扩充 `tests/components/Sidebar.test.tsx`、`tests/lib/fs.test.ts`；E2E 改用 `expandMockNotes` 按需展开断言。

## 二、同步原生控件与主题配色（issue #14 / PR #16）

### 现象

切换深色/浅色主题后，代码块语言下拉框、滚动条等**原生控件**仍保持浅色外观，与整体主题不一致；Linux 上尤为明显。

### 根因

CSS 未声明 `color-scheme`，浏览器无法得知根元素/代码块的预期配色方案，原生控件按系统默认（通常浅色）渲染。

### 修复

`src/App.css`：
- `:root,[data-theme="light"]` 补 `color-scheme: light`；`[data-theme="dark"]` 补 `color-scheme: dark`。
- 代码块按 `data-code-theme` 同步：`.code-block[data-code-theme="oneDark"]` 设 `color-scheme: dark`，`[data-code-theme="light"]` 设 `color-scheme: light`，使代码块内原生控件跟随代码高亮主题而非全局主题。

### 测试

`tests/e2e/theme-settings.spec.ts` SE3 扩展为断言 `html` 与语言下拉框的 `color-scheme` 在明暗/代码主题切换下正确联动。

## 三、打开文件时保留侧边栏文件树（issue #12 / PR #17）

### 现象

从侧边栏点击打开文件时，文件树会被全局「加载中」占位替换并重新挂载，导致：①文件树滚动位置丢失；②展开状态视觉跳动；③大目录重新加载造成卡顿。

### 根因

`openFile` 复用了工作区加载态（`loading`/`workspaceLoading`）来提示「正在打开」，该态会触发文件树组件以占位 UI 重新挂载，丢弃既有 DOM 实例与滚动位置。

### 修复

**行内局部状态替代全局加载态**（`Sidebar.tsx` / `workspace.ts`）：
- 新增 `openingFiles: Set<string>` 与 `fileOpenErrors: Map<string,string>`，文件读取期间在对应行显示行内 spinner，失败显示错误图标（可点击重试），不再替换整棵文件树。
- 文件树 DOM 实例与滚动位置在打开文件全程保持不变。

**竞态处理**（`workspace.ts`）：
- 同一文件的并发打开只读取一次并创建一个标签页。
- 后打开的文件完成时保持最后点击项为活跃；读取期间切换标签页不会被旧结果抢回焦点（`mainFileIntent`/`splitFileIntent` 代际计数）。
- 分屏与主面板并发选择同一文件时关闭重复分屏；工作区加载与单文件打开相互交错时后发起的上下文优先。
- `App.tsx`/`GlobalSearchPanel.tsx` 的 `open`/`openFile` 调用补 `.catch`，避免未处理拒绝；全局搜索跳转前校验当前文件是否仍为命中文件。

### 测试

`tests/store/workspace-tree.test.ts` 新增「文件读取与标签页竞态」「分屏与工作区上下文竞态」两大组；`tests/components/Sidebar.test.tsx` 验证读取未加载文件时保留 DOM 与滚动位置、失败可重试；E2E `editor.spec.ts` 新增从侧边栏打开文件保留文件树实例与滚动位置的用例。

## 四、Release 增加 Linux amd64 构建（issue #13 / PR #18）

### 现状

仓库仅有 `build-windows.yml`，`test`/`build` job 固定 `windows-latest`；tag 构建只发布 NSIS exe / MSI / 便携 zip。Linux amd64 用户只能自行拉源码、装 Node/Rust/Tauri 系统依赖后本地构建。

### 修复

将 `build-windows.yml` 整合为统一的 `.github/workflows/build.yml`：

| job | runner | 职责 |
|-----|--------|------|
| `test` | windows-latest | 单元/组件测试 + Playwright E2E（平台无关，原逻辑不变） |
| `build-windows` | windows-latest | NSIS exe + MSI + 便携 zip，上传 artifact（不再内联发 Release） |
| `build-linux` | ubuntu-22.04 | 装 Tauri 2 系统依赖，`pnpm tauri build --bundles appimage,deb` 产出 AppImage + deb |
| `release` | ubuntu-latest | tag 推送时下载两端全部产物，附加到同一 GitHub Release |

**关键设计**：
- Linux 依赖：`libwebkit2gtk-4.1-dev` / `libjavascriptcoregtk-4.1-dev` / `libsoup-3.0-dev` / `libgtk-3-dev` / `libappindicator3-dev` / `librsvg2-dev` / `librsvg2-bin` / `patchelf` 等。
- 显式 `--bundles appimage,deb`，避免 rpm bundler 缺依赖导致失败（rpm 后续可按需加）。
- 独立 `release` job 依赖 `[build-windows, build-linux]`，下载所有 artifact 后一次性创建 Release，避免两个 build job 并发创建 Release 的竞争。
- 产物缺失时 `if-no-files-found: error` 与 `fail_on_unmatched_files: true` 直接失败，不静默发布不完整产物。
- 普通 `main` 推送只跑 test/build（artifact），`release` job 仅在 `v*` tag 时运行，不误建 Release。

### 验收

- 文件名含版本与架构（如 `InklingMD_2.1.0_amd64.AppImage` / `.deb`）。
- 现有 Windows 构建逻辑不变（仅 Release 步骤迁移到独立 job，产物一致）。
- README 徽章由 `build-windows.yml` 同步为 `build.yml`。
