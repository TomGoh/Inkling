## 任务：工具栏 5 个边界 bug 修复

### Bug 清单

| # | 用户操作 | 报错/现象 | 根因 |
|---|---|---|---|
| 1 | 光标在元数据（frontmatter）上点「删除块」 | 误删文档底部块 | `deleteCurrentBlock` 用 `$head.before(1)` 找顶层块，但 atom 节点 NodeSelection 下 `$head` 位置语义错误 |
| 2 | 点击目录块（toc）再点「删除块」 | 无反应 | 同 #1，toc 是 atom 节点 |
| 3 | 工具栏点两次删除线（hr） | `there is no position after the top-level node` | `insertBlockHere` 在文档最后一个块调用 `$from.after($from.depth)` 越界 |
| 4 | 点两次有序/无序列表 | `invalid content for node list_item` | 列表内重复 wrap 产生 list_item > list_item 非法嵌套 |
| 5 | 代码块内点列表/引用 | `content does not fit in gap` | code_block content 是 `text*`，不能被 wrap 进 list_item/blockquote |

### 技术方案

#### Bug 1 & 2：`deleteCurrentBlock` 识别 NodeSelection

**原逻辑**（[block-commands.ts](file:///workspace/src/components/Editor/block-commands.ts)）：

```typescript
const { $head } = state.selection;
if ($head.depth === 0) return;
const topPos = $head.before(1);  // ← atom 节点 NodeSelection 下返回错误位置
const topNode = state.doc.nodeAt(topPos);
```

**问题**：atom 节点（frontmatter/toc/hr/math）被点击选中时是 `NodeSelection`，`$head` 指向节点边界，`$head.before(1)` 可能返回错误位置（如文档末尾），导致删错块或删不到。

**修复**：优先识别 `NodeSelection`，直接拿选中的节点和位置：

```typescript
export function deleteCurrentBlock(view: EditorView): void {
  const { state } = view;
  let topPos: number;
  let topNode: Node | null | undefined;

  if (state.selection instanceof NodeSelection) {
    // atom 节点被选中（frontmatter/toc/hr/math_display 等）
    topPos = state.selection.from;
    topNode = state.doc.nodeAt(topPos);
  } else {
    const { $head } = state.selection;
    if ($head.depth === 0) return;
    try {
      topPos = $head.before(1);
    } catch {
      return;
    }
    topNode = state.doc.nodeAt(topPos);
  }
  if (!topNode) return;
  // ... 删除 + 补空段落 + 光标定位
}
```

光标定位也改用 `TextSelection.near(resolve, -1)` 优先向前找，避免 `topPos - 1` 在 `topPos=0` 时变成 -1。

#### Bug 3：`insertBlockHere` 文档末尾块越界

**原逻辑**：

```typescript
const pos = $from.after($from.depth);  // ← 文档最后一个块时抛错
view.dispatch(view.state.tr.insert(pos, node).scrollIntoView());
```

**问题**：`$from.after($from.depth)` 在文档最后一个顶层块时抛 `there is no position after the top-level node`。

**修复**：try/catch + 夹值到文档末尾：

```typescript
const docSize = view.state.doc.content.size;
let pos: number;
try {
  pos = $from.after($from.depth);
} catch {
  pos = docSize;
}
pos = Math.min(pos, docSize);
view.dispatch(view.state.tr.insert(pos, node).scrollIntoView());
```

#### Bug 4：列表内重复 wrap

**原逻辑**：

```typescript
const range = $from.blockRange($to);
view.dispatch(view.state.tr.wrap(range, [{ type: listType }, { type: listItem }]));
```

**问题**：光标已在列表内时，`range.parent` 是 `list_item`，再 wrap 一层 `list > list_item` 产生 `list_item > list > list_item` 非法嵌套（list_item content 是 `paragraph` 不允许直接含 list_item）。

**修复**：检测 `range.parent` 已是 list_item 时跳过：

```typescript
if (range.parent.type.name === "list_item") {
  view.focus();
  return;
}
```

#### Bug 5：code_block / atom 节点 wrap 报错

**问题**：
- code_block 的 content 是 `text*`，不能被 wrap 进 blockquote（content `paragraph+`）或 list_item（content `paragraph`）
- atom 节点（frontmatter/toc/hr/math）被 NodeSelection 选中时，`$from.blockRange` 返回的 range 指向 doc 级别，wrap 会把整个文档结构搞乱

**修复**：
1. NodeSelection 选中 atom 节点时直接跳过：
```typescript
function isAtomSelected(view: EditorView): boolean {
  const { selection } = view.state;
  return (
    selection instanceof NodeSelection &&
    Boolean((selection.node.type as unknown as { atom?: boolean }).atom)
  );
}
```
（`atom` 是 NodeSpec 属性，运行时挂在 NodeType 上，但 TypeScript 类型定义未暴露，用 `as unknown as` 绕过）

2. code_block 检测：
```typescript
if (range.parent.type.name === "code_block") {
  view.focus();
  return;
}
```

3. try/catch 兜底所有 wrap 调用，避免遗漏的边界情况抛错打断用户：
```typescript
try {
  view.dispatch(view.state.tr.wrap(range, [...]).scrollIntoView());
} catch {
  // wrap 失败（content 不匹配等）时静默忽略
}
```

### 验收

| 场景 | 修复前 | 修复后 |
|---|---|---|
| frontmatter 上点删除块 | 误删底部块 | 正确删除 frontmatter |
| toc 上点删除块 | 无反应 | 正确删除 toc |
| 文档末尾点两次删除线 | 报错 | 正常插入 |
| 列表内点两次列表 | 报错 invalid content | 静默跳过 |
| 代码块内点列表 | 报错 content does not fit | 静默跳过 |
| 代码块内点引用 | 报错 | 静默跳过 |
| atom 节点上点列表 | 报错 | 静默跳过 |
