# v2.3.9 设计文档

> 主题：批量修复缺陷与安全 Issue #68-#72——reloadFile 强制刷新富文本编辑器（#68）、Mermaid 渲染 SVG 安全过滤（#69）、openFile 异常状态兜底清理（#70）、外部冲突保留修改基线同步（#71）、Windows 盘符路径归一化（#72）。

***

## 背景

在代码审查与使用中发现 5 项基础缺陷与安全问题，涵盖编辑器内容重载、SVG XSS 注入防范、文件树 Loading 状态机健壮性、外部文件冲突基线同步以及跨平台路径判定。本版本针对这 5 个 Issue 进行集中修复并补齐相关自动化测试。

## #68 reloadFile 触发后富文本 WYSIWYG 编辑器未同步更新

**问题**：当触发外部文件变更重载或冲突对话框选择“重载磁盘版本”时，Zustand store 中的 `currentContent` 已更新，但由于 `App.tsx` 中 `<Editor key={currentFile}>` 的 `key` 仅绑定了文件路径，Milkdown 编辑器内部仍保留旧的 ProseMirror 文档树，导致后续用户编辑会把旧内容覆盖写回磁盘。

**修复**：
1. `OpenTab` 结构中引入 `revision: number` 版本递增序号。
2. 在 `reloadFile` 成功重读磁盘内容后，执行 `t.revision = (t.revision || 0) + 1` 自增。
3. 在 `App.tsx` 与 `SplitPane.tsx` 中将编辑器 Key 升级为 `key={`${currentFile}-${revision}`}`，保证磁盘重载时强制卸载并重构最新编辑器视图。

## #69 Mermaid 动态渲染 SVG 缺乏清洗存在 XSS 风险

**问题**：`mermaid-view.ts` 渲染出的 SVG 内容直接通过 `diagram.innerHTML = svg` 挂载到 DOM 中。若 Markdown 文件中包含构造的恶意 SVG（含 `<script>` 或 `javascript:` 伪协议超链接），可能在 WebView 内部触发脚本执行。

**修复**：
1. 在 `html-view.ts` 的 `sanitizeHTML` 中扩展 SVG 标准图形标签（`svg`, `g`, `path`, `circle`, `text`, `clipPath` 等）及图形属性白名单。
2. 在 `mermaid-view.ts` 中使用 `diagram.appendChild(sanitizeHTML(svg))` 替换原有的直接 `innerHTML` 插入，阻断恶意脚本。

## #70 openFile 异常时 openingFiles 状态未被清理

**问题**：`openFile` 在读取磁盘或准备 tab 过程中如果发生非受控异常，原先在末尾手动清除 `openingFiles[filePath]` 的逻辑会被跳过，导致侧边栏文件树的该项一直显示加载动画。

**修复**：
将 `openFile` 核心逻辑包裹在 `try ... finally` 中，确保无论成功、失败还是抛出异常，`openingFiles` 状态必定在 `finally` 块中清理。

## #71 外部文件冲突选择「保留我的修改」后未更新基线导致重复弹窗

**问题**：当用户在 `ConflictDialog` 中点击“保留当前编辑”时，只关闭了弹窗，但 tab 的 `diskContent` 基准内容未更新。下一次保存时，保存前的基准比对仍然会发现 `latestOnDisk !== tab.diskContent` 而再次弹出冲突。

**修复**：
1. `tabs.ts` 中新增 `setTabDiskContent(path, diskContent)` action。
2. 在 `ConflictDialog` 点击“保留我的修改”时，调用 `setTabDiskContent` 将冲突时的磁盘内容设为当前 tab 的新基线，消除后续保存的重复弹窗。

## #72 Windows 盘符大小写不一致导致路径判定失效

**问题**：Windows 系统下不同 API 返回的盘符大小写可能不一致（如 `C:/workspace` vs `c:/workspace`），`isPathWithin` 进行前缀比对时会判定为不在工作区内。

**修复**：
在 `isPathWithin` 中先使用统一正则对盘符进行大写归一化处理（`normalizeDriveLetter`），再进行目录从属判断。
