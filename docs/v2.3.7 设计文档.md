# v2.3.7 设计文档

> 主题：外部文件变动冲突对话框（用户口头反馈，未建 issue）+ 发版前置校验（CI release-guard）。

***

## 背景

用户口头反馈（未建 issue）：`useFileWatcher` 监听文件变动，当本地编辑器处于脏状态（有未保存修改）且外部文件发生改变（Git 切分支、网盘同步）时，存在数据安全风险。

### 排查结论

原实现「静默重载丢失内容」**不成立**——dirty 时有 `window.confirm` 明确询问「是否丢弃当前修改并重新加载」，不会静默丢数据。但反馈中「忽略外部变动则容易引发覆盖写入」**成立**：

- 用户选「取消」（继续编辑）后，稍后 Ctrl+S 保存会把本地内容**静默覆盖**磁盘上的外部修改，无备份、无 diff 感知；
- confirm 只有两选项（丢弃重载 / 忽略），没有「保留本地并另存副本」「先看差异再决定」的安全路径；
- 反馈建议的三选项（另存副本 / 丢弃重载 / Diff 对比）正是补齐这块短板。

## 方案一：外部文件变动冲突对话框（用户口头反馈）

### 触发条件

`useFileWatcher` 每 3 秒轮询活跃文件 mtime，检测到外部修改时：

| 状态 | 原行为 | 新行为 |
| --- | --- | --- |
| `dirty === false` | confirm 询问重载 | 保持不变（confirm 询问重载） |
| `dirty === true` | confirm 二选一（丢弃重载 / 忽略） | **弹冲突对话框**（四选项 + Diff） |
| 磁盘读取失败 | confirm 询问 | 保持 confirm 兜底（文件被删等场景） |

冲突对话框已打开时轮询跳过，避免重复弹窗。

### 对话框四选项

1. **保留本地并另存副本**：本地内容写入 `<name>.backup.md`（已占用则 `.backup.2.md`、`.backup.3.md`… 自动递增），随后编辑器重载磁盘最新版本。**两侧内容都不丢**；
2. **查看差异**：展开行级 diff 视图（unified 风格，标注「本地未保存」与「磁盘外部修改」两侧），再决定；
3. **丢弃本地修改，重载磁盘最新**：直接 `openFile` 重载；
4. **继续编辑**：明示「稍后保存将覆盖磁盘上的外部修改」，关闭对话框。

### 行级 Diff 算法（[diff.ts](../src/lib/diff.ts)）

自研 LCS（最长公共子序列）行级 diff，不引入第三方依赖：

1. **公共前后缀修剪**：先跳过首尾相同的行，仅对中间差异段做 DP，大幅缩小问题规模；
2. **LCS 动态规划**：`Uint32Array` 二维表逆序递推，回溯生成 `equal / remove / add` 三类操作；
3. **大差异降级**：差异段超过 4000 行时跳过 DP，整块输出 `remove` + `add`（O(n) 而非 O(n·m)），避免大文件卡 UI；
4. **备副本命名**（`nextBackupPath`）：`file.md` → `file.backup.md`，占用则 `file.backup.2.md`… 上限 1000 个，兜底时间戳后缀；路径比较统一小写归一（Windows 大小写不敏感文件系统）。

### 状态与组件

- [conflict.ts](../src/store/conflict.ts)：Zustand store，仅存 `conflict: FileConflict | null`（filePath / localContent / diskContent / detectedAt）+ `openConflict` / `dismiss`；
- [ConflictDialog.tsx](../src/components/FileConflict/ConflictDialog.tsx)：对话框本体，Diff 视图 `useMemo` 惰性计算（点开才 diff），各选项处理中置 busy 防重复点击；
- [useFileWatcher.ts](../src/lib/useFileWatcher.ts)：dirty 分支改为读磁盘内容 → `openConflict`；读取期间用户切文件则按路径核对放弃弹窗；
- [App.tsx](../src/App.tsx)：挂载 `<ConflictDialog />`。

### 测试（22 个新用例）

- [diff.test.ts](../tests/unit/diff.test.ts)（14 个）：全等 / 全新增 / 全删除 / 头尾插入 / 中间修改 / 空串 / CRLF / 行尾差异 / 大文本降级 / 备份命名（首个 / 递增 / 跳过已占用 / 大小写归一 / 无扩展名）；

## 方案二：发版前置校验（CI release-guard）

### 需求

用户要求：文档更新与版本号同步约束**仅在打 release 时强制**，平时开发者提交不受影响。

### 实现（[build.yml](../.github/workflows/build.yml)）

新增 `release-guard` job：

```yaml
release-guard:
  if: startsWith(github.ref, 'refs/tags/')   # 仅 tag 推送时执行
  ...
  - run: node scripts/check-version.mjs --tag=${{ github.ref_name }}
  - run: |
      PREV_TAG=$(git tag --sort=-v:refname --list 'v*' | grep -v "^${{ github.ref_name }}$" | head -n 1)
      node scripts/check-docs-updated.mjs --base="$PREV_TAG" --head=HEAD
release:
  needs: [build-windows, build-linux, release-guard]   # 校验失败阻止 Release
```

- **无 pre-commit hook、无 push main 校验**：日常提交零影响；
- release job `needs: release-guard`，校验失败则 Release 不发布。

### 校验 1：版本号一致性（[check-version.mjs](../scripts/check-version.mjs)）

打新 release 包需同步更新 **4 处版本号**：

| 文件 | 字段 |
| --- | --- |
| `package.json` | `version` |
| `src-tauri/tauri.conf.json` | `version` |
| `src-tauri/Cargo.toml` | `[package] version` |
| `src-tauri/Cargo.lock` | `inklingmd` 包 `version` |

要求四处完全一致，且与 tag 名（`v2.3.7` ↔ `2.3.7`）一致。

### 校验 2：文档同步（[check-docs-updated.mjs](../scripts/check-docs-updated.mjs)）

比较上一 tag → HEAD 的变更：若 `src/` 或 `src-tauri/` 有代码变更，则以下文档**至少一处**必须更新（否则 exit 1）：

- `CHANGELOG.md`（变更记录，必更）
- `README.md`（版本记录 / 功能说明）
- `docs/`（设计文档 / 需求文档）
- `ARCHITECTURE.md` / `CONTRIBUTING.md`

纯文档 / CI 变更不触发要求；首个 tag（无历史）跳过。
