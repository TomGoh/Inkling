# v2.3.2 设计文档

> 主题：万行多图文档滚动掉帧修复（Mermaid 空闲预渲染）。

---

## 背景

v2.3.1 修复了万行多图文档"打开冻结"（视口懒渲染，打开时长任务 ~7s → ~2s）。用户实测反馈：打开明显改善，但**滚轮滚动仍掉帧**，体感与 v2.2 相当、远不如 v2.1——v2.1.0 打开时同步渲染全部 60 张图（冻结 ~10s），之后滚动全程顺滑。

## 定位过程

### 假设一：v2.2 引入的 outline 自动跟随（scroll → posAtCoords）拖慢滚动

v2.1.0 的 outline-tracker 无任何 scroll 监听；v2.2.0（`409d3db`）为"大纲自动跟随当前章节"新增 scroll → rAF → `posAtCoords` 采样路径。但实测排除：

- 纯文本区滚动（260k→310k px，无图表）：**0 长任务**，`getBoundingClientRect` 仅 ~2 次/帧（466 次 / 223 帧）
- outline 每帧两次 rect + posAtCoords 命中测试在此文档规模下开销可忽略

### 假设二：v2.3.0 的 cursor-saver 滚动落盘（#30）

scroll 监听只做 `scrollTop` 读取 + 300ms 防抖 timer 重置，落盘写 zustand 且订阅方选择器为稳定函数引用，不触发重渲染。排除。

### 实锤：Chrome DevTools performance trace 的 ForcedReflow insight

滚动期强制回流耗时大头全部来自 **Mermaid 渲染内部**：

| 调用帧 | 回流耗时 |
|---|---|
| addHtmlSpan（mermaid） | 933ms |
| drawText（sequenceDiagram） | 257ms |
| addText（mermaid common） | 224ms + 157ms |
| draw（ganttDiagram） | 151ms |
| insertEdge / insertEdgeLabel | 150ms + 114ms |
| updateNodeBounds | 169ms |

**根因**：v2.3.1 的视口懒渲染把渲染开销从"打开时"转移到"滚动时"——滚到未渲染图表处逐张 ~150ms 卡顿，图表密集区连续掉帧。这是懒加载策略的固有副作用，需要在"打开快"与"滚动顺"之间补一座桥。

## 修复设计

[mermaid-view.ts](../src/components/Editor/mermaid-view.ts) 新增**空闲预渲染队列**，形成三层渲染策略：

1. **视口即时渲染**（保留 v2.3.1 行为）：IntersectionObserver（300px 预载边距）触发即渲染，保证滚到即见；
2. **空闲预渲染**（本次新增）：打开文档后，视口外图表按创建（文档）顺序排入模块级队列，`requestIdleCallback` 每个空闲槽渲染一张——每张 ~150ms 超出单帧预算，逐张让出主线程，把 v2.1 的"打开集中冻结 10s"化为"打开后空闲时段后台分摊 ~10s"；
3. **滚动让位**：document 级捕获 scroll 监听（passive）记录最近滚动时间，停歇不足 250ms 时暂停出队，避免后台预渲染与滚动争抢主线程；滚得快落在未预渲染图表时由第 1 层兜底。

关键实现（模块级）：

```ts
const idleRenderQueue: Array<() => void> = [];
function pumpIdleRenderQueue(): void {
  // ... 每个空闲槽 shift 一张渲染；滚动停歇 <250ms 时 setTimeout 顺延
}
```

NodeView 侧以 `firstRenderDone` 门控首次渲染：视口路径与空闲任务共用 `renderFirst()`（幂等），谁先到谁渲染；容器销毁（切文档）后队列任务经 `container.isConnected` 守卫自动跳过。`update()` 在未首渲染时只更新 `current` 引用，待渲染时用最新内容。

## 验证数据（生产构建 + Chrome DevTools）

| 场景 | v2.3.1 | v2.3.2 |
|---|---|---|
| 打开时长任务 | 1.9s（4 个） | 1.9s（不变） |
| 打开后静止 16s（无滚动） | 视口外 0/60 渲染 | **59/60 后台渲染完成** |
| 全文滚动（0→末尾，3000px/350ms） | 51 长任务 / 4195ms | **27 长任务 / 2780ms，平均 90fps** |
| 快速滚动多图区（6000px/100ms） | 多次 150ms+ 冻结 | **1 长任务 / 50ms** |

剩余 27 个长任务主要为 170 个代码块的 CodeMirror 懒挂载（v1.2.0 起即有的模式，v2.1.0 同样存在，非回归）；其中最差 180ms。
