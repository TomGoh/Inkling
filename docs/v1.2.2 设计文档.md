## 任务 1：Ctrl+滚轮缩放文档

### 目标

支持 `Ctrl/Cmd+滚轮` 等比放大/缩小整个文档（50%~300%，步进 10%），`Ctrl/Cmd+0` 重置 100%，缩放级别跨会话持久化，状态栏显示当前百分比并可点击重置。

### 技术方案

#### 1.1 状态层：settings store 扩展

修改 [settings.ts](file:///workspace/src/store/settings.ts)：新增 `editorZoom` 状态与三个方法。

```typescript
export const ZOOM_MIN = 0.5;
export const ZOOM_MAX = 3;
export const ZOOM_STEP = 0.1;
export const ZOOM_DEFAULT = 1;

export interface SettingsState {
  // ... 原有字段
  editorZoom: number;
  adjustEditorZoom: (delta: number) => void;  // 增量调整
  setEditorZoom: (v: number) => void;          // 直接设置
  resetEditorZoom: () => void;                 // 重置 100%
}

/** 将任意倍率夹到合法范围，并保留一位小数避免浮点累积误差 */
function clampZoom(v: number): number {
  const rounded = Math.round(v * 10) / 10;
  return Math.min(ZOOM_MAX, Math.max(ZOOM_MIN, rounded));
}
```

关键设计点：
- 持久化到 localStorage（复用现有 `inkling-settings` key），跨会话恢复。
- `clampZoom` 同时做范围夹值和一位小数修正，避免 `0.1 + 0.2 = 0.30000000000000004` 这类浮点累积导致状态栏百分比抖动。
- 初始值从持久化读取后也走一次 `clampZoom`，防御历史脏数据（如手动改 localStorage 写入 5.0）。

#### 1.2 事件监听：App.tsx

修改 [App.tsx](file:///workspace/src/App.tsx)：新增 wheel 监听与 Ctrl+0 快捷键。

```typescript
// Ctrl/Cmd + 滚轮缩放文档：拦截浏览器原生页面缩放，改用应用内 zoom
// passive:false 才能 preventDefault；capture 阶段拦截确保不被其他处理消耗
useEffect(() => {
  const onWheel = (e: WheelEvent) => {
    if (!(e.ctrlKey || e.metaKey)) return;
    e.preventDefault();
    // 向上滚（deltaY < 0）放大，向下滚缩小
    useSettings.getState().adjustEditorZoom(e.deltaY < 0 ? ZOOM_STEP : -ZOOM_STEP);
  };
  window.addEventListener("wheel", onWheel, { passive: false, capture: true });
  return () => window.removeEventListener("wheel", onWheel, { capture: true } as EventListenerOptions);
}, []);
```

在已有 keydown handler 中追加（紧接 Ctrl+Alt+0 转段落之后）：

```typescript
// Ctrl/Cmd+0 重置编辑器缩放到 100%（浏览器/Typora 标准）
if (!e.shiftKey && !e.altKey && e.key === "0") {
  e.preventDefault();
  useSettings.getState().resetEditorZoom();
  return;
}
```

关键设计点：
- wheel 监听必须 `passive: false` 才能 `preventDefault` 拦截浏览器原生缩放（否则 Ctrl+滚轮会缩放整个 WebView 而非文档）。
- 用 `capture: true` 在捕获阶段拦截，确保在 Milkdown/ProseMirror 的 bubble 阶段之前生效，不被编辑器内部处理消耗。
- 通过 `useSettings.getState()` 而非闭包变量读取 store，避免 useEffect 依赖 `adjustEditorZoom` 导致频繁重订阅。
- Ctrl+0 与 Ctrl+Alt+0（转段落）通过 `e.altKey` 区分，互不冲突。

#### 1.3 缩放应用：CSS zoom 属性

给三处 `.editor-scroll` 容器加 `style={{ zoom: editorZoom }}`：
- 禅模式编辑器
- 主面板编辑器（含查找面板）
- 分屏右侧面板编辑器

```tsx
<div className="editor-scroll" style={{ zoom: editorZoom }}>
```

**为什么用 CSS `zoom` 而非 `transform: scale`**：
- `zoom` 会同步调整布局尺寸（占位、滚动条、可点击区域都跟随缩放），无需手动补偿 transform 的视觉与布局错位问题。
- Tauri WebView2（Windows）基于 Chromium，完全支持 `zoom`；macOS WKWebView 也支持。
- `transform: scale` 只改变视觉不改变布局，会导致滚动条范围、点击命中区域与视觉位置错位，需大量补偿代码，且 ProseMirror 的 `posAtCoords` 会因 transform 偏移而计算错误。
- 三处编辑器共享同一 `editorZoom` 状态，分屏时两侧同步缩放。

#### 1.4 状态栏显示

修改 [StatusBar.tsx](file:///workspace/src/components/StatusBar/StatusBar.tsx)：右侧追加缩放百分比按钮。

```tsx
<button
  type="button"
  className={`status-item status-zoom${editorZoom === ZOOM_DEFAULT ? "" : " status-zoom-active"}`}
  title="点击重置为 100% (Ctrl/Cmd+0)"
  onClick={() => resetEditorZoom()}
>
  {zoomPct}%
</button>
```

- 用 `status-spacer`（flex:1）把缩放按钮推到状态栏最右，与左侧字数统计分立两端。
- 非 100% 时加 `status-zoom-active` class 高亮加粗，提示用户当前处于缩放态。
- 点击按钮调用 `resetEditorZoom()`，与 Ctrl+0 等效，提供鼠标用户的重置入口。

#### 1.5 快捷键帮助

修改 [ShortcutsHelp.tsx](file:///workspace/src/components/Shortcuts/ShortcutsHelp.tsx)：「视图与布局」组追加两项。

```typescript
{ keys: `${MOD}+滚轮`, desc: "放大 / 缩小文档（50% ~ 300%）" },
{ keys: `${MOD}+0`, desc: "重置缩放到 100%" },
```

### 验收
- `Ctrl/Cmd+滚轮上` 放大 10%，上限 300%
- `Ctrl/Cmd+滚轮下` 缩小 10%，下限 50%
- `Ctrl/Cmd+0` 重置 100%
- 状态栏右侧显示当前百分比，非 100% 时高亮，点击重置
- 缩放级别跨会话持久化（重启应用恢复）
- 禅模式、主面板、分屏三处编辑器均响应缩放
- 既有 `Ctrl/Cmd+Alt+0`（转段落）不受影响

## 任务 2：修复 GitHub Action Node.js 20 弃用警告

### 目标

消除 GitHub Action 运行时的 `Node.js 20 is deprecated` 警告。

### 问题根因

`actions/upload-artifact@v5` 的 [action.yml](https://github.com/actions/upload-artifact/blob/v5/action.yml) 仍声明 `runs.using: 'node20'`，GitHub 强制用 Node 24 运行时给出弃用警告。v5 并未升级到 node24，只有 v6/v7 才是 `using: 'node24'`。

### 技术方案

修改 [.github/workflows/build-windows.yml](file:///workspace/.github/workflows/build-windows.yml)：两处 `actions/upload-artifact@v5` → `@v7`。

```yaml
# Upload Playwright report / Upload installers
uses: actions/upload-artifact@v7
```

- v7.0.1 是当前最新稳定版，已验证 action.yml 为 `using: 'node24'`。
- 其他 actions（checkout@v5、setup-node@v5、pnpm/action-setup@v5）未报警告，已是 node24，无需改动。
- v7 相比 v5 新增 `archive` 输入（默认 true，行为与 v5 一致），无需调整 with 参数。

### 验收
- GitHub Action 运行日志不再出现 `Node.js 20 is deprecated` 警告
- Playwright report 与安装包产物正常上传
