# Markdown 编辑器 —— 技术方案 & 任务拆解（面向 Coding Agent）

> 配套文档：`Markdown编辑器需求文档.md`（产品需求）
> 本文档目的：把需求转化为 coding agent 可以逐步执行、可验收的开发任务
> 使用方式：**不要把全部任务一次性丢给 agent**，按阶段逐个丢，每个任务做完你验收一次再进入下一个

---

## 1. 技术选型（已锁定并落地）

| 层 | 实际选型 | 理由 |
|---|---|---|
| 应用外壳 | **Tauri 2.x** | 包体小、性能好、Rust 后端更安全，适合本地文件读写类应用 |
| 前端框架 | **React 19 + TypeScript** | 生态成熟，Milkdown 官方对 React 支持最完善 |
| 编辑器内核 | **Milkdown 7.x**（基于 ProseMirror） | 开源、已实现所见即所得，覆盖大部分 Markdown 语法，避免自研内核 |
| 状态管理 | **Zustand 5** | 轻量，够用，比 Redux 简单 |
| 样式 | **纯 CSS + CSS 变量**（用于主题切换） | 轻量、无构建开销，CSS 变量足够支撑明暗模式与自定义主题 |
| 公式渲染 | **KaTeX**（`@milkdown/plugin-math` + remark-math） | 比 MathJax 快 |
| 图表 | **Mermaid 11**（代码块渲染钩子 `mermaid-view.ts`） | 官方库，文档全 |
| 代码高亮 | **CodeMirror 6**（`@codemirror/language` 系列） | 可在 Milkdown 节点视图内嵌入，支持 ~100 种语言 |
| PDF/HTML 导出 | **HTML 直接序列化；PDF 走浏览器打印** | 不依赖外部 Pandoc，零安装成本 |
| Word 导出 | **Rust command 调用本地 `pandoc` 二进制**（`std::process::Command`） | 不引入 tauri-plugin-shell；未安装 pandoc 时返回明确错误，前端引导用户安装 |
| 文件系统 | Tauri `fs` / `dialog` 插件 + 自定义 Rust command | 原生支持，命令集中在 `src-tauri/src/commands/mod.rs` |

**与初版方案的差异说明：**
- 初版建议 Tailwind CSS，实际改为纯 CSS + CSS 变量。项目体量不大，Tailwind 引入额外构建复杂度收益有限，CSS 变量已足够支撑主题系统。
- 初版建议 Shiki 做代码高亮，实际改用 CodeMirror 6。CodeMirror 可作为 Milkdown 代码块节点视图内嵌编辑器，做到「代码块内也能直接编辑+高亮」，比 Shiki 的纯渲染更符合 WYSIWYG 体验。
- 初版建议 Pandoc 做 PDF 导出，实际改为浏览器打印（`window.print()`）。零安装、零外部依赖，对个人使用足够；Word 导出在 v0.6.0 走 Pandoc。
- 快捷键自定义：仅暴露应用级快捷键（查找/侧边栏/大纲/帮助/设置）给用户自定义，编辑器内 Milkdown 预设快捷键不在自定义范围内，避免破坏编辑器内部行为。

**技术选型验证（已完成）：** 最小 Tauri + React + Milkdown 项目已跑通，Milkdown 覆盖了标题、加粗、斜体、列表、任务列表、表格、代码块、图片插入等全部验证项。

## 2. 项目结构（实际）

```
inkling/
├── src-tauri/                    # Rust 后端
│   ├── src/
│   │   ├── main.rs               # 入口
│   │   ├── lib.rs                # Tauri Builder 注册命令
│   │   └── commands/
│   │       ├── mod.rs            # 文件系统命令（list_dir/read_text_file/write_text_file/write_binary_file/file_mtime）
│   │       └── pandoc.rs         # Pandoc 调用（pandoc_check/pandoc_export_docx）
│   ├── capabilities/default.json # Tauri 2 权限配置
│   ├── Cargo.toml
│   └── tauri.conf.json
├── src/                          # 前端
│   ├── components/
│   │   ├── Editor/               # Milkdown 编辑器封装 + 插件
│   │   │   ├── Editor.tsx        # 主编辑器
│   │   │   ├── TableToolbar.tsx  # 表格工具栏
│   │   │   ├── code-block-view.ts# 代码块节点视图（嵌入 CodeMirror）
│   │   │   ├── image-node-view.ts# 图片节点视图
│   │   │   ├── image-upload.ts   # 拖拽/粘贴图片上传
│   │   │   ├── link-click.ts     # Ctrl/Cmd+点击跟随链接
│   │   │   ├── math.ts           # KaTeX 数学公式插件
│   │   │   ├── mermaid-view.ts   # Mermaid 图表节点视图
│   │   │   └── outline-tracker.ts# 光标位置 → 大纲高亮联动
│   │   ├── Sidebar/              # 文件树侧边栏
│   │   ├── Tabs/                 # 多标签页栏
│   │   ├── Outline/              # 大纲面板（标题跳转）
│   │   ├── Settings/             # 偏好设置面板
│   │   ├── Shortcuts/            # 快捷键帮助与自定义面板
│   │   └── StatusBar/            # 字数统计状态栏
│   ├── lib/
│   │   ├── fs.ts                 # 前端 fs 封装（Tauri/浏览器双实现）
│   │   ├── exporter.ts           # HTML/PDF/Word 导出 + 复制为富文本/Markdown
│   │   ├── outline.ts            # 标题大纲解析
│   │   ├── stats.ts              # 字数统计
│   │   ├── useAutoSave.ts        # 自动保存 Hook
│   │   └── useFileWatcher.ts     # 文件外部修改监听 Hook
│   ├── store/
│   │   ├── workspace.ts          # 工作区状态（文件树、多标签页、当前文件镜像）
│   │   ├── theme.ts              # 主题状态（明暗模式、自定义 CSS）
│   │   ├── settings.ts           # 偏好设置（专注/打字机/公式编号/代码主题）
│   │   ├── ui.ts                 # UI 可见性（侧边栏/大纲显隐）
│   │   └── shortcuts.ts          # 应用级快捷键自定义绑定
│   ├── App.tsx
│   └── App.css
├── docs/                         # 需求文档与技术方案
└── package.json
```

**约定 agent 遵守：**
- 前后端通信统一走 `src-tauri/src/commands/` 里定义的 command，不允许前端直接拼路径操作文件系统之外的逻辑
- 每个功能模块一个文件夹，不许把所有逻辑塞进 `App.tsx`
- 所有新增依赖需在任务说明里注明，不许静默引入未讨论过的库

## 3. 分阶段任务清单

> 每个任务给 agent 时，格式建议：「实现 X 功能，验收标准是 Y，不要涉及 Z」
> 状态图例：✅ 已完成（含发布版本） / ⏳ 待开发

### 阶段一：骨架与基础编辑（对应 PRD P0 前半部分） ✅ v0.1.0

- [x] **任务1**：初始化 Tauri + React + TS 项目，跑通"打开一个空窗口"
  - 验收：`pnpm tauri dev` 能正常启动窗口
- [x] **任务2**：集成 Milkdown，实现一个占满窗口的编辑区域，能输入纯文本并支持基础 Markdown 快捷语法（标题/加粗/斜体/列表/引用/分割线）
  - 验收：输入 `# 标题` 自动变成大号加粗标题样式；输入 `**加粗**` 光标离开后正确渲染
- [x] **任务3**：实现"打开文件夹" + 文件树侧边栏，点击 `.md` 文件在编辑区加载内容
  - 验收：选择一个包含多个 md 文件的文件夹，树状展示，点击切换正确加载对应内容
- [x] **任务4**：实现保存（Ctrl/Cmd+S）与自动保存（防抖 2 秒）
  - 验收：编辑后不手动保存，2 秒后文件内容已写入磁盘（可用外部编辑器验证）
- [x] **任务5**：状态栏字数统计（字数/字符数/预计阅读时长）
  - 验收：实时随编辑更新

### 阶段二：核心语法补全（对应 PRD P0 后半部分） ✅ v0.2.0

- [x] **任务6**：表格支持（插入、拖拽调整列宽、行列增删）
  - 落地：`TableToolbar.tsx` 提供行列增删、对齐、网格选择器插入
- [x] **任务7**：代码块 + 语法高亮，支持切换语言
  - 落地：改用 CodeMirror 6（替代初版 Shiki），`code-block-view.ts` 作为节点视图嵌入
- [x] **任务8**：图片插入（拖拽/粘贴），自动复制到工作区 `assets/` 文件夹并用相对路径引用
  - 落地：`image-upload.ts` + `image-node-view.ts`
- [x] **任务9**：链接（含内部锚点跳转到标题）
  - 落地：`link-click.ts`，Ctrl/Cmd+点击跟随链接

> 每完成 2-3 个任务，建议让 agent 写一份简短的"实现说明"，方便你复查逻辑是否合理，而不是全靠肉眼测 UI。

### 阶段三：进阶功能（对应 PRD P1） ✅ v0.3.0

- [x] **任务10**：数学公式（KaTeX 行内/块级渲染）—— `math.ts`

## 4. 给 coding agent 的通用约束（建议放进每次任务的提示词里）

1. 每次只做一个任务，不要顺带"顺手"实现后面阶段的功能
2. 完成后用一两句话说明改动了哪些文件、新增了哪些依赖
3. 遇到"选型建议"里没写清楚的细节（如某个 UI 交互怎么做），先给出你的方案说明，不要直接替我做决定后不声明
4. 涉及文件系统读写的代码，必须做错误处理（文件不存在、无权限等），不能假设一定成功
5. 不引入未讨论过的第三方付费/云服务

---

## 5. 建议的验收方式

- 每个任务合并前，实际打开应用手动测一遍，而不是只看 agent 的"完成"陈述
- 阶段一、阶段二完成后，用真实的一篇长笔记（比如你之前写的技术笔记）测试实际编辑体验，越早发现体验问题成本越低
- 阶段三之后，可以开始每周跑一次"回归测试"：随手写点内容，检查所有已实现功能是否还正常
