# Markdown 编辑器 —— 技术方案 & 任务拆解（面向 Coding Agent）

> 配套文档：`Markdown编辑器需求文档.md`（产品需求）
> 本文档目的：把需求转化为 coding agent 可以逐步执行、可验收的开发任务
> 使用方式：**不要把全部任务一次性丢给 agent**，按阶段逐个丢，每个任务做完你验收一次再进入下一个

---

## 1. 技术选型（已锁定并落地）

| 层 | 实际选型 | 理由 |
|---|---|---|
| 应用外壳 | **Tauri 2.x** | 包体小、性能好、Rust 后端更安全，适合本地文件读写类应用 |
| 前端框架 | **React 19 + TypeScript** | 生态成熟，Milkdown 官方对 React 支持最完善 |
| 编辑器内核 | **Milkdown 7.x**（基于 ProseMirror） | 开源、已实现所见即所得，覆盖大部分 Markdown 语法，避免自研内核 |
| 状态管理 | **Zustand 5** | 轻量，够用，比 Redux 简单 |
| 样式 | **纯 CSS + CSS 变量**（用于主题切换） | 轻量、无构建开销，CSS 变量足够支撑明暗模式与自定义主题 |
| 公式渲染 | **KaTeX**（`@milkdown/plugin-math` + remark-math） | 比 MathJax 快 |
| 图表 | **Mermaid 11**（代码块渲染钩子 `mermaid-view.ts`） | 官方库，文档全 |
| 代码高亮 | **CodeMirror 6**（`@codemirror/language` 系列） | 可在 Milkdown 节点视图内嵌入，支持 ~100 种语言 |
| PDF/HTML 导出 | **HTML 直接序列化；PDF 走浏览器打印** | 不依赖外部 Pandoc，零安装成本 |
| Word 导出 | **Rust command 调用本地 `pandoc` 二进制**（`std::process::Command`） | 不引入 tauri-plugin-shell；未安装 pandoc 时返回明确错误，前端引导用户安装 |
| 文件系统 | Tauri `fs` / `dialog` 插件 + 自定义 Rust command | 原生支持，命令集中在 `src-tauri/src/commands/mod.rs` |

**与初版方案的差异说明：**
- 初版建议 Tailwind CSS，实际改为纯 CSS + CSS 变量。项目体量不大，Tailwind 引入额外构建复杂度收益有限，CSS 变量已足够支撑主题系统。
- 初版建议 Shiki 做代码高亮，实际改用 CodeMirror 6。CodeMirror 可作为 Milkdown 代码块节点视图内嵌编辑器，做到「代码块内也能直接编辑+高亮」，比 Shiki 的纯渲染更符合 WYSIWYG 体验。
- 初版建议 Pandoc 做 PDF 导出，实际改为浏览器打印（`window.print()`）。零安装、零外部依赖，对个人使用足够；Word 导出在 v0.6.0 走 Pandoc。
- 快捷键自定义：仅暴露应用级快捷键（查找/侧边栏/大纲/帮助/设置）给用户自定义，编辑器内 Milkdown 预设快捷键不在自定义范围内，避免破坏编辑器内部行为。

**技术选型验证（已完成）：** 最小 Tauri + React + Milkdown 项目已跑通，Milkdown 覆盖了标题、加粗、斜体、列表、任务列表、表格、代码块、图片插入等全部验证项。

**约定 agent 遵守：**
- 前后端通信统一走 `src-tauri/src/commands/` 里定义的 command，不允许前端直接拼路径操作文件系统之外的逻辑
- 每个功能模块一个文件夹，不许把所有逻辑塞进 `App.tsx`
- 所有新增依赖需在任务说明里注明，不许静默引入未讨论过的库

### 阶段补丁：编辑器性能优化 ✅ v0.9.x

> 目标：消除每次按键/光标移动时的无谓 O(N) 全树遍历与 store 高频写入，将长文档输入延迟增长曲线压平。架构层面基于 ProseMirror 增量 transaction + Tauri 轻量外壳，已优于 MarkText（Muya + marked.js 全量 re-parse 架构）；本次补丁把应用层可优化的部分做到位。

- [x] **性能优化 1**：插件回调加 `docChanged` / `recalc` 守卫
  - `formula-numbering.ts`：`appendTransaction` 改为仅在 `docChanged` 或收到 `recalc` meta 时执行；新增 `hasMathDisplay` 短路（无公式节点直接返回）。消除每个 transaction（含纯光标移动）的全树 `descendants` 扫描。功能开关切换时由 `Editor.tsx` dispatch 带 `recalc: true` 的空 tr 显式触发重算。
  - `block-drag.ts`：手柄装饰集缓存到 plugin state，仅在 doc 变更或 `dropIndex` 变化时重建，纯选区移动复用缓存。消除每次按键的 `forEach` + `createElement`。
  - `outline.ts`：`findActiveHeadingIndex` 从 O(n) 线性扫描改为 O(log n) 二分查找，并加首尾短路。
- [x] **性能优化 2**：cursor-saver 改为本地缓存 + 防抖落 store
  - `Editor.tsx` 的 `inkling-cursor-saver` 插件：光标位置缓存到闭包变量，防抖 300ms、失焦、销毁时才写 store。消除每次光标移动都 `set({ openTabs })` 导致 TabsBar / useAutoSave 的全局重渲染。
- [x] **性能优化 3**：TabsBar / useAutoSave 精准订阅
  - `TabsBar.tsx`：改为订阅 `path|dirty|isUntitled` 的字符串快照，content 变化不再重渲染。
  - `useAutoSave.ts`：改为订阅「活跃 tab 是否未命名」布尔派生值，避免每次按键 effect 重订阅。
- [x] **性能优化 4**：代码块 NodeView 视口懒挂载
  - `code-block-view.ts`：CodeMirror 实例延迟到代码块进入视口（`IntersectionObserver`，rootMargin 200px 预加载）时才创建；`update` 在实例未创建时仅更新 node 引用。大量代码块文档下避免一次性初始化上百个 CodeMirror 实例。
- [x] **性能优化 5**：查找面板输入防抖
  - `SearchPanel.tsx`：查找词 120ms 防抖，连续输入只触发一次全文匹配。

**客观定位（与主流编辑器对比）**：
- 中小文档（千行内）：与 Typora 体感基本拉平，明显优于 MarkText
- 长文档（万行级）：仍不及 Typora（自研增量渲染 + 懒布局），但输入延迟增长曲线比 MarkText 平缓（增量 transaction vs 全量 re-parse）
- 启动/内存：Tauri 外壳远优于 MarkText（Electron）
- 仍存在的架构限制（非本次范围）：ProseMirror 全量 DOM 渲染（无虚拟滚动）；Milkdown `markdownUpdated` 每键全文序列化 O(N)；Mermaid/KaTeX 无渲染缓存

## 4. 给 coding agent 的通用约束（建议放进每次任务的提示词里）

1. 每次只做一个任务，不要顺带"顺手"实现后面阶段的功能
2. 完成后用一两句话说明改动了哪些文件、新增了哪些依赖
3. 遇到"选型建议"里没写清楚的细节（如某个 UI 交互怎么做），先给出你的方案说明，不要直接替我做决定后不声明
4. 涉及文件系统读写的代码，必须做错误处理（文件不存在、无权限等），不能假设一定成功
5. 不引入未讨论过的第三方付费/云服务

## 5. 建议的验收方式

- 每个任务合并前，实际打开应用手动测一遍，而不是只看 agent 的"完成"陈述
- 阶段一、阶段二完成后，用真实的一篇长笔记（比如你之前写的技术笔记）测试实际编辑体验，越早发现体验问题成本越低
- 阶段三之后，可以开始每周跑一次"回归测试"：随手写点内容，检查所有已实现功能是否还正常
