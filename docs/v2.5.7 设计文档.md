# v2.5.7 设计文档

## 一、问题背景与根因分析

### 1.1 触发场景
在桌面端（Tauri）运行 InklingMD 时，用户执行关闭窗口操作（点击窗口关闭按钮、快捷键或退出机制）：
```
用户触发关闭
  → App.tsx exitHandler 拦截关闭事件并完成未保存 Tab 落盘
  → 调用 getCurrentWindow().destroy() 真正销毁窗口关闭应用
  → 触发 Tauri 全局错误弹窗："Command plugin:window|destroy not allowed by ACL"
```

### 1.2 根因
Tauri 2.x 引入了细粒度能力权限控制（Capabilities / ACL）。在 `src-tauri/capabilities/default.json` 中配置了 `core:window:allow-create`，但缺少对 `core:window:allow-destroy` 和 `core:window:allow-close` 的显式授权，导致退出流程调用底层窗口销毁指令时被安全策略拒绝。

---

## 二、架构决策与防御设计

### 2.1 权限授权
在 `src-tauri/capabilities/default.json` 的 `permissions` 列表中补充：
- `"core:window:allow-destroy"`：允许退出时彻底销毁 Webview 窗口；
- `"core:window:allow-close"`：允许标准关闭窗口指令。

### 2.2 防回归单测守护
在 `tests/unit/capabilities.test.ts` 中增加断言，确保 CI 在每次构建时严格验证 ACL 权限完整性：
```typescript
it("包含 window destroy 与 close 权限（窗口退出逻辑需要）", () => {
  expect(permissions).toContain("core:window:allow-destroy");
  expect(permissions).toContain("core:window:allow-close");
});
```
