# v2.3.0 设计文档

> 主题：万行文档性能回退修复（#31）+ 源码模式增强（#26/#27/#28/#29）+ 保存链路稳健性（PR #34）+ 社区修复（#30/#36）。

---

## 背景

v2.2.0 引入源代码模式后，出现两方面的回归：①**万行文档编辑/滚动掉帧**——`markdown-publisher` 保存路径对每个挂载编辑器重复全文序列化，长文档出现明显卡顿（issue #31）；②**打开文件被误判 dirty**——编辑器初始化的首个 flush 因序列化规范化差异把从未编辑的文档标脏，导致关闭 tab 误弹未保存确认（E2E「关闭 tab」失败根因）。

同时源码模式还留有四个增强点：#26 光标/滚动映射粗糙（纯行数线性比例在代码块/空行场景偏差大）、#27 退出源码模式后 Ctrl+Z 会退回旧文档、#28 缺少可访问性语义、#29 源码模式下查找替换只能用 alert 提示退出。

此外合并了社区贡献者 @TomGoh 的两个修复（issue #30 多标签滚动/光标位置串扰、issue #36 macOS E2E 平台按键），并处理了 PR #34 保存链路的多轮 review 意见。

## 一、万行文档编辑/滚动掉帧修复（issue #31）

### 现象

打开万行级 Markdown 文档后，输入/滚动明显掉帧；切换标签页时卡顿数秒。

### 根因

`markdown-publisher.ts` 的 `flush` 在**无待发编辑**（timer 为 null）时仍执行——保存路径对每个挂载的编辑器都调用 `flush`，即使该编辑器没有任何 pending 编辑。每次调用都触发一次全文序列化（`deps.serialize(view.state.doc)`），万行文档的序列化是大停顿。

### 修复

[markdown-publisher.ts](src/components/Editor/markdown-publisher.ts) 的 `flush` 开头加守卫：timer 为 null（无待发编辑）直接跳过，不重复全文序列化。

```ts
const flush = () => {
  // 无待发编辑（timer 为 null）直接跳过：保存路径的 flush 不应
  // 对每个挂载编辑器重跑全文序列化（万行文档的大停顿，PR #34）。
  if (!timer) return;
  ...
};
```

### 测试

随 PR #34 review 一并验证：`tests/unit/markdown-publisher.test.ts` 调整断言聚焦 flush/防循环行为本身。

## 二、打开文件不再误判 dirty（E2E「关闭 tab」修复）

### 现象

E2E 测试中打开文件后直接关闭 tab，关闭按钮不生效——Playwright 断言 tab 数从 2 减到 1 失败。

### 根因

`markdown-publisher` 在 view 创建时把**原始文件内容**（`value`）设为同步基线 `lastSynced`。但 Milkdown 解析后 doc 的序列化结果与原始内容存在规范化差异（如末尾换行）。编辑器初始化的首个 flush 因此被判定为「变更」，经 `onChange → setContent` 把从未编辑的文档标 dirty，触发关闭确认对话框（Playwright 自动 dismiss），关闭被取消。

### 修复

view 创建时用**解析后 doc 的实际序列化结果**重置基线，而非原始文件内容：

```ts
view: (view) => {
  let timer = null;
  // 打开文件时以「解析后 doc 的实际序列化结果」为基线，而非原始文件内容。
  // 否则编辑器初始化的首个 flush 会因序列化规范化差异把从未编辑的文档误判为
  // 变更、经 onChange 标 dirty，导致关闭 tab 时误弹未保存确认。
  try {
    deps.setLastSynced(deps.serialize(view.state.doc));
  } catch {
    // 序列化失败保持原基线，flush 时再兜底
  }
  ...
}
```

配套在 [Editor.tsx](src/components/Editor/Editor.tsx) 增加 `initialSyncDoneRef`：编辑器刚以当前 value 完成初始化时跳过外部同步 effect，避免每次挂载把 doc 冗余重灌一遍。

### 测试

修复 `tests/unit/markdown-publisher.test.ts`（view 创建时基线调用计数、按测试意图复位 `lastSynced`）；E2E「关闭 tab」系列用例恢复通过。

## 三、源码模式查找替换（issue #29）

### 背景

v2.2.0 源码模式下，全局 `Ctrl/Cmd+F` / `Ctrl/Cmd+R` 只弹 alert 提示「请退出源码模式」。本版本改为路由到 CodeMirror 内置查找/替换面板。

### 设计

- 新增 [source-mode-search.ts](src/lib/source-mode-search.ts)：文件路径 → 命令执行器的注册表。`SourceModeEditor` 挂载时 `registerSourceModeSearch(filePath, run)`，卸载时注销；`runSourceModeSearch(filePath, { replace })` 对指定路径的源码模式编辑器执行查找/替换命令，未注册（非源码模式）时返回 false 由 App.tsx 兜底走 WYSIWYG 的 SearchPanel。
- [App.tsx](src/App.tsx) 的 Ctrl+R / Ctrl+F 分支：先查 `getTabSourceMode(activeTabPath)`，源码模式则 `runSourceModeSearch`，否则保持原有 WYSIWYG 查找替换。
- [SourceModeEditor.tsx](src/components/Editor/SourceModeEditor.tsx)：`useLayoutEffect` 中注册命令执行器，replace 模式用 `replaceNext`（未选中匹配时打开面板，否则逐个替换），否则 `openSearchPanel`。
- [codemirror-shared.ts](src/lib/codemirror-shared.ts)：源码模式扩展加入 `search({ top: true })` + `searchKeymap` + `{ key: "Mod-r", run: replaceNext }`。
- [ShortcutsHelp.tsx](src/components/Shortcuts/ShortcutsHelp.tsx)：查找/替换快捷键说明更新。

### 关键坑：@codemirror/search 版本差异

`@codemirror/search@6.7.1` **已移除 `replace` 命令**（替换框内建进搜索面板，用 `replaceNext`/`replaceAll` 替代）。旧代码 `import { replace }` 导致模块加载即抛 `SyntaxError: does not provide an export named 'replace'`，应用白屏、所有 E2E 全挂。修复为使用 `replaceNext`，并新增依赖 `@codemirror/search@^6.7.1`。

### 测试

单元测试 `tests/unit/source-mode-cursor.test.ts` 等补齐；全量 E2E 138 passed 覆盖源码模式查找路由。

## 四、光标/滚动映射增强（issue #26）

### 背景

v2.2.0 的 `markdownOffsetToProsePos` 用纯行数线性比例把源码 offset 映射到 PM 位置，遇到围栏代码块/空行偏差大；`prosePosToMarkdownOffset` 全量 `textBefore` 匹配在多块文档（PM 用单个 `\n` 连接块、markdown 块间是空行）时失败。

### 修复

[source-mode-cursor.ts](src/lib/source-mode-cursor.ts)：

- 新增 `computeLineWeights(markdown)`：解析每行的「PM 权重」——围栏代码块内部行权重极小（0.02，整个代码块在 PM 里只是一个 `code_block` 节点）、空行权重 0、其余每行权重 1。
- `markdownOffsetToProsePos` 改为按「光标之前已完成行权重和 + 当前行内比例」占全文权重和的比例映射到 docSize，越界/空文档有确定性兜底。
- `prosePosToMarkdownOffset` 增加「当前行片段匹配」：全量 textBefore 匹配失败时，用光标所在行的文本片段从后往前定位，避免多块文档因分隔符差异丢失定位。

### 测试

`tests/unit/source-mode-cursor.test.ts` 新增 `computeLineWeights` 围栏/空行用例、`prosePosToMarkdownOffset` 多块文档片段定位用例等，11 个用例全过。

## 五、退出源码模式重置撤销历史（issue #27）

### 现象

源码模式下编辑 → 切回 WYSIWYG 后按 Ctrl+Z，文档退回切换前的旧快照，与当前 markdown 不一致。

### 根因

退出源码模式时整文档替换（`replaceWith(0, docSize, newDoc)`）后，PM 的 history 插件仍保留指向旧快照的 undo 步骤。

### 修复

[Editor.tsx](src/components/Editor/Editor.tsx) 在整文档替换事务上重置 history：找到 `history` 插件实例（key 以 `"history"` 开头），把 `historyState` meta 灌入 `historyPlugin.spec.state.init()`（初始空状态），让撤销从退出源码模式后的首次编辑开始。注意 history 插件 key 是 `history$` 前缀且模块私有，需通过插件实例拿真实 key、用同一字符串键 setMeta 才能被 `applyTransaction` 命中。

```ts
const historyPlugin = view.state.plugins.find((p) => p.key.startsWith("history"));
if (historyPlugin) {
  tr = tr.setMeta(historyPlugin.key, {
    historyState: historyPlugin.spec.state.init(),
  });
}
view.dispatch(tr);
```

## 七、Markdown 往返保真单测（issue #25）

### 背景

v2.2.0 源代码模式上线后，设计文档 §5 推荐的 round-trip 单元测试未落地，自定义块（callout、frontmatter、mermaid、math、toc）的 serialize → parse 回归缺少保护，后续改 Milkdown 插件时容易引入静默数据变形。

### 设计

新增 [source-mode-roundtrip.test.ts](tests/unit/source-mode-roundtrip.test.ts)：搭建**无头 Milkdown 编辑器**（与 [Editor.tsx](src/components/Editor/Editor.tsx) 同款 commonmark + gfm + math/frontmatter/toc/callout 的 schema 与 remark 插件；不装配视图层插件——NodeView/KaTeX/CodeMirror 渲染与解析序列化无关），从 `parserCtx` / `serializerCtx` 取真实解析/序列化管线。

断言三层：
1. **节点层**：解析后 doc 中存在预期节点类型与关键 attr（callout 的 calloutType、frontmatter 的 value、code_block 的 language="mermaid"、math_inline/math_display 的 LaTeX value、toc 节点）
2. **文本层**：序列化结果保留关键语法标记与内容子串（`> [!Type]`、YAML 键值、```` ```mermaid ````、`$...$`、`[TOC]`）
3. **幂等性**：`serialize(parse(md))` 后再往返一次不变——首次往返允许规范化差异（空行数量、列表 marker 统一、`[` 转义为 `\[`），第二次起必须稳定，否则源码模式反复进出会持续改写用户文件

9 个用例：callout 基本往返 / WARNING 大小写规范化 / Obsidian 写法归一、frontmatter、mermaid、math、toc、混合文档（五类自定义块共存互不干扰）、GFM 基线（任务列表勾选态/表格/strike_through mark/脚注不因自定义插件引入而退化）。

### 测试驱动的真 bug 修复：toc 序列化静默丢失 `[TOC]`

测试落地即抓到一个数据丢失 bug：`toc.ts` 的 `toMarkdown` runner 写了 `state.addNode("paragraph", undefined, "[TOC]")`，而 serializer `addNode` 的签名是 `(type, children?, value?, props?)`——第 2 参是 **children**。把文本传到 value 位后段落无子节点，字符串化输出空行，`[TOC]` 完全消失。

触发路径：WYSIWYG 模式下用户对含 `[TOC]` 的文档做任意编辑 → `markdown-publisher` 序列化整篇 doc → onChange 把丢失 `[TOC]` 的 markdown 写回 store → **保存落盘的文件 TOC 块被静默删除**，重新打开后目录块消失。

修复：改用与 callout 相同的 `openNode("paragraph") → addNode("text", undefined, "[TOC]") → closeNode()` 写法，显式构建段落文本子节点。

### 知识点备忘

- milkdown gfm 任务列表复用 commonmark 的 `listItem` 节点（`checked` attr 扩展），无独立 `taskItem` 节点类型；勾选态保真在序列化层断言（`[x]` / `[ ]` 原样写出）
- 删除线的 mark 类型名是 `strike_through`（下划线风格），脚注定义节点名是 `footnote_definition`——`doc.descendants` 只遍历节点，mark 需从 `node.marks` 找
- `[`、`!` 等字符序列化时会转义（`\[!Note]`），re-parse 后还原，不影响幂等性断言

## 八、保存链路稳健性（PR #34）

处理 PR #34 多轮 review，涉及保存/发布链路的竞态修复：

- **异步发布绑定文件路径**：`markdown-publisher` 异步发布时绑定文件路径，修复 tab 切换串写（切到另一 tab 后旧 tab 的 flush 写错文件）。
- **防抖窗口内编辑到点先 flush**：自动保存定时器到点时先 flush 防抖窗口内累积的编辑再落盘，避免丢编辑。
- **手动保存/关闭/swap 路径先 flush**：手动保存、关闭 tab、分屏 swap 前都先 flush，保证已输入内容不丢。
- **dirty 状态镜像同步**：分屏/多面板场景下 dirty 状态镜像同步，避免一屏标记另一屏漏标。
