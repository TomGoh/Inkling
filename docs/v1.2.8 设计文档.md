## 任务 1：行内公式插入功能

### 背景

v1.2.6 已修复块级公式（`$$...$$`）插入「不能用」，但行内公式（`$...$`）此前只能靠手写 `$...$` 语法让 remark-math 解析生成，没有工具栏 / 斜杠菜单入口。用户反馈「怎么新加行内公式啊」，本版补齐两个可视化入口。

### 技术方案

#### 1.1 `insertInlineMath` 命令

[block-commands.ts](file:///workspace/src/components/Editor/block-commands.ts) 新增：

```typescript
export function insertInlineMath(view: EditorView): void {
  const t = view.state.schema.nodes.math_inline;
  if (!t) return;
  const node = t.create();
  const { from } = view.state.selection;
  // 行内节点直接 insert 在光标处（不替换段落）
  view.dispatch(view.state.tr.insert(from, node).scrollIntoView());
  // 下一帧选中并触发编辑模式
  requestAnimationFrame(() => {
    try {
      const sel = NodeSelection.create(view.state.doc, from);
      view.dispatch(view.state.tr.setSelection(sel));
      const dom = view.nodeDOM(from) as HTMLElement | null;
      if (dom) {
        dom.dispatchEvent(new MouseEvent("dblclick", { bubbles: true }));
      }
    } catch { /* 静默失败 */ }
  });
  view.focus();
}
```

要点：
- `math_inline` 是 inline + atom 节点，直接 `tr.insert(from, node)` 插在光标处（不像块级公式需要 `replaceWith` 替换空段落）
- 复用 v1.2.6 的「插入后自动 NodeSelection + 模拟 dblclick」模式，让用户插入后立即进入 LaTeX 编辑态，无需手动双击
- 空值时 [math.ts](file:///workspace/src/components/Editor/math.ts) 的 `createMathView` 显示「公式」占位提示，避免节点不可见

#### 1.2 工具栏按钮

[TableToolbar.tsx](file:///workspace/src/components/Editor/TableToolbar.tsx) 在块级公式按钮旁追加：

```tsx
<button className="tt-btn" onClick={() => withView(insertInlineMath)} title="行内公式">$ 行内</button>
```

#### 1.3 斜杠菜单选项

[slash-menu.ts](file:///workspace/src/components/Editor/slash-menu.ts) 在块级公式之后追加行内公式命令：

```typescript
if (schema.nodes.math_inline) {
  cmds.push({
    label: "行内公式",
    keywords: "math formula 公式 inline 行内",
    icon: "$",
    run: (v, anchor) => {
      const tr = v.state.tr.deleteRange(anchor, v.state.selection.from);
      const node = schema.nodes.math_inline.create();
      const pos = tr.selection.from;
      tr.insert(pos, node);
      v.dispatch(tr.scrollIntoView());
      requestAnimationFrame(() => {
        try {
          const sel = NodeSelection.create(v.state.doc, pos);
          v.dispatch(v.state.tr.setSelection(sel));
          const dom = v.nodeDOM(pos) as HTMLElement | null;
          if (dom) dom.dispatchEvent(new MouseEvent("dblclick", { bubbles: true }));
        } catch { /* 静默失败 */ }
      });
      v.focus();
    },
  });
}
```

### 验收

| 入口 | 操作 | 结果 |
|---|---|---|
| 工具栏 | 正文段落内点 `$ 行内` | 光标处出现行内公式节点并自动进入编辑态 |

## 任务 2：frontmatter 删除块误删底部块（彻底修复）

### 背景

v1.2.7 已尝试修复「光标在元数据（frontmatter）上点删除块误删底部块」，方案是 [frontmatter.ts](file:///workspace/src/components/Editor/frontmatter.ts) 加 `mousedown` 监听主动设置 `NodeSelection`。但用户反馈「这个问题没有修好」——实际场景下仍会误删。

### 根因分析

frontmatter 节点内嵌了 CodeMirror 编辑器。当用户在 CodeMirror 内编辑 YAML 时：

1. `mousedown` 监听确实设置了 `NodeSelection`
2. 但 CodeMirror 的 `focus()` / `setNodeAttribute` 触发的事务会**冲掉** `NodeSelection`，把 selection 改回 `TextSelection`
3. 此时 `view.state.selection` 指向 CodeMirror 内部某个文本位置，但 `$head.before(1)` 算出的顶层块位置可能是**之前光标所在的块**（往往是文档底部某个段落）
4. 点「删除块」时 `deleteCurrentBlock` 拿到旧 `TextSelection`，于是误删底部块

### 修复方案

[block-commands.ts](file:///workspace/src/components/Editor/block-commands.ts) `deleteCurrentBlock` 增加 **DOM 焦点回退路径**：

```typescript
function atomNodeFromDom(view, el) {
  // 向上走直到 view.dom 的直接子节点（某个顶层块的 DOM）
  let cur = el;
  while (cur && cur.parentElement !== view.dom) cur = cur.parentElement;
  if (!cur) return null;
  // 用兄弟计数得到该块在顶层的孩子索引
  let idx = 0, sib = cur;
  while (sib && sib.previousElementSibling) { idx++; sib = sib.previousElementSibling; }
  const doc = view.state.doc;
  if (idx >= doc.childCount) return null;
  let pos = 0;
  for (let i = 0; i < idx; i++) pos += doc.child(i).nodeSize;
  const node = doc.child(idx);
  // 只对 atom 节点走 DOM 路径，普通块仍走 selection 路径
  if (!node.type.atom) return null;
  return { pos, node };
}
```

`deleteCurrentBlock` 在 `selection` 不是 `NodeSelection` 时，读 `document.activeElement` 反查所属 atom 顶层块：

```typescript
if (state.selection instanceof NodeSelection) {
  topPos = state.selection.from;
  topNode = state.doc.nodeAt(topPos);
} else {
  // DOM 焦点回退：CodeMirror 获得焦点时 selection 可能被冲掉
  const active = document.activeElement;
  if (active && view.dom.contains(active)) {
    const hit = atomNodeFromDom(view, active);
    if (hit) { topPos = hit.pos; topNode = hit.node; }
  }
  if (topNode == null) {
    // 回退到原 TextSelection 路径
    const { $head } = state.selection;
    ...
  }
}
```

同时 [TableToolbar.tsx](file:///workspace/src/components/Editor/TableToolbar.tsx) 「删除块」按钮加 `onMouseDown={e => e.preventDefault()}`，阻止按钮抢走 CodeMirror 焦点（否则点击瞬间 `activeElement` 变成按钮本身，DOM 回退失败）。

### 为什么 v1.2.7 没修好

v1.2.7 的 `mousedown` 监听只在点击瞬间设置 `NodeSelection`，但 CodeMirror 后续的 focus/事务会把它冲掉。到点「删除块」按钮时（通常已过了几秒，用户在 CM 内输入了内容），`selection` 早已不是 `NodeSelection`。必须从「当前真实焦点」反查才能定位到 frontmatter。

### 验收

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 在 frontmatter 的 CM 内编辑后点删除块 | 误删底部块 | 正确删除 frontmatter |
| 在普通段落点删除块 | 正常 | 正常（走 TextSelection 路径） |
| NodeSelection 选中 atom 节点点删除块 | 正常 | 正常（优先走 NodeSelection 路径） |

## 任务 3：列表内点代码块/表格按钮报错

### 背景

用户反馈「在有序或无序列表里点工具栏代码块或者表格之类的按钮会报错 `invalid content for node list_item`」。

### 根因

`list_item` 的 content 是 `paragraph block*`——**第一个子节点必须是 paragraph**。

- `turnIntoCodeBlock` 调 `setNodeMarkup` 把当前 paragraph 改成 code_block → 违反规则
- `insertTable` 把 table 插到 list_item 第一位 → 违反规则

### 修复方案

[block-commands.ts](file:///workspace/src/components/Editor/block-commands.ts) 新增 `exitListIfNeeded`：

```typescript
export function exitListIfNeeded(view: EditorView): boolean {
  const { $head } = view.state.selection;
  let listDepth = -1;
  for (let d = $head.depth; d > 0; d--) {
    const name = $head.node(d).type.name;
    if (name === "bullet_list" || name === "ordered_list") { listDepth = d; break; }
  }
  if (listDepth === -1) return false;
  // 在列表之后插入空段落，光标移过去
  let listEnd = $head.after(listDepth);
  listEnd = Math.min(Math.max(listEnd, 0), view.state.doc.content.size);
  const para = view.state.schema.nodes.paragraph.create();
  const tr = view.state.tr.insert(listEnd, para);
  tr.setSelection(TextSelection.near(tr.doc.resolve(listEnd + 1)));
  view.dispatch(tr);
  return true;
}
```

`setBlockType`（标题/代码块/Mermaid 共用）开头先调用 `exitListIfNeeded`，退出后再 `setNodeMarkup`；[TableToolbar.tsx](file:///workspace/src/components/Editor/TableToolbar.tsx) `insertTable` 在调 `insertTableCommand` 前先 `exitListIfNeeded`。

### 嵌套列表场景

`$head.after(listDepth)` 返回**最内层** list 的末尾，新段落落到外层 `list_item` 下作为其第二个子节点（`block*`），仍然合法。不会破坏嵌套结构。

### 验收

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 无序列表内点代码块 | 报错 `invalid content for node list_item` | 列表保留，code_block 插到列表后 |
| 有序列表内点表格 | 报错 | 列表保留，table 插到列表后 |
| 有序列表内点标题 | 报错 | 列表保留，heading 插到列表后 |
| 普通段落点代码块 | 正常 | 正常（`exitListIfNeeded` 返回 false） |
