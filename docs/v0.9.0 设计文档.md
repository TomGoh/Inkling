## 任务 36：多面板分屏

### 目标
标签页右键「在分屏打开」启动右侧第二面板，双编辑器实例独立编辑两个文件，支持左右交换。

### 技术方案

修改 [workspace.ts](file:///workspace/src/store/workspace.ts)：新增分屏状态与方法。

```typescript
// 分屏：右侧第二面板，独立展示另一个已打开的 tab
splitFile: string | null;        // 分屏面板展示的文件路径（null 表示未分屏）
splitContent: string;            // 分屏面板内容（从对应 tab 实时同步）
splitOpen: (filePath: string) => Promise<void>;   // 在分屏打开（确保已 openFile，但不切主面板活跃 tab）
splitClose: () => void;                            // 关闭分屏
splitSwap: () => void;                             // 主面板与分屏面板文件互换
setSplitContent: (content: string) => void;        // 分屏编辑时更新内容并同步到 tab（标记 dirty）
```

关键设计点：
- `splitOpen` 复用 `openFile` 确保文件在 `openTabs` 中，但记录并切回原活跃 tab，避免分屏操作抢走主面板焦点。
- `setSplitContent` 同步写入对应 tab 的 content 并置 `dirty: true`，保证分屏编辑的文件能被自动保存与 dirty 标记。
- 关闭标签页 / 关闭其他 / 关闭右侧 / 全部关闭 / 文件重命名时，若影响分屏文件则同步关闭分屏或更新路径（`closeTab` / `closeOthers` / `closeAll` / `onFileRenamed` 内处理）。
- 不允许分屏文件与主文件相同（无对照意义），`splitOpen` 内拦截。

修改 [App.tsx](file:///workspace/src/App.tsx)：编辑器渲染区改为 `.editor-body` flex 容器，分屏时加 `editor-body-split` class 横向排列主面板与 `.split-pane`。分屏面板含独立头部（文件名 + 交换 ⇄ + 关闭 ✕）与第二个 `MarkdownEditor` 实例，`onChange` 接 `setSplitContent`。

修改 [TabContextMenu.tsx](file:///workspace/src/components/Tabs/TabContextMenu.tsx)：新增「在分屏打开」菜单项，调用 `splitOpen`；当前主文件或已在分屏中时禁用。

修改 [App.css](file:///workspace/src/App.css)：新增 `.editor-body` / `.editor-body-split` / `.split-pane` / `.split-pane-header` / `.editor-scroll-split-pane` 样式。

### 验收
- 打开两个文件，在其中一个标签页右键「在分屏打开」，右侧出现第二面板
- 两侧可独立编辑，分屏文件改动同步 dirty 标记与自动保存
- ⇄ 按钮交换左右文件，✕ 关闭分屏
- 关闭分屏文件的标签页时分屏面板自动关闭

## 任务 37：拖拽块排序

### 目标
每个顶层块节点左侧悬停出现 ⋮⋮ 手柄，按住拖动整块重排，drop 指示器高亮目标位置。

### 技术方案

新建 [block-drag.ts](file:///workspace/src/components/Editor/block-drag.ts)：ProseMirror 插件，基于 Decoration + HTML5 DnD。

```typescript
export const blockDragKey = new PluginKey("inkling-block-drag");
export const blockDragPlugin = () => new Plugin({ ... });
```

实现要点：
- `decorations`：遍历 `doc` 顶层子节点，在每个块起始位置用 `Decoration.widget(pos, createHandle, { side: -1 })` 插入手柄 span。手柄 `data-block-pos` 记录块起始位置，`draggable=true`。
- 插件 state `dropIndex`：记录当前 drop 目标块索引，null 表示无。
- `dragstart`（handleDOMEvents）：识别手柄目标，`topLevelBlockAt` 找到所属顶层块，`dataTransfer` 携带 `{ pos, size }`（自定义 mime `application/x-inkling-block`），并用该块 DOM 副本做拖拽预览。
- `dragover`：仅响应本插件发起的拖拽（检查 `dataTransfer.types`），`posAtCoords` 计算指针所在块，按块中点决定插「之前 / 之后」得到 `dropIndex`，dispatch meta 更新指示器装饰。
- `drop`：解析源块 `{ pos, size }`，按 `dropIndex` 累加前 N 个块大小得到目标位置；单个 transaction 内 `delete` 源块再 `insert` 到目标位置（删除在前需修正目标偏移：`src.pos < targetPos` 时 `adjustedTarget -= src.size`）。
- `dragend`：清除 dropIndex。

修改 [Editor.tsx](file:///workspace/src/components/Editor/Editor.tsx)：注入 `blockDragPlugin()`。

修改 [App.css](file:///workspace/src/App.css)：`.inkling-block-handle`（绝对定位左侧 -1.75rem，hover 显现）、`.inkling-drop-indicator`（蓝色 2px 横线）。

### 验收
- 块左侧悬停出现 ⋮⋮ 手柄
- 拖动手柄整块移动，蓝色横线指示插入位置
- 释放后块重排，撤销可恢复

## 任务 38：导出长图（PNG）

### 目标
整篇文档渲染成 2x 高清 PNG 长图，桌面端写文件 / 浏览器端下载。

### 技术方案

修改 [exporter.ts](file:///workspace/src/lib/exporter.ts)：新增 `exportPNG`。

```typescript
export async function exportPNG(getEditor: () => Editor | undefined): Promise<void>
```

实现：
- 动态 `import("html2canvas")`（按需加载，不进主 bundle）。
- 复用 `getEditorHTML` 取编辑器渲染后 DOM（移除 ProseMirror 编辑态属性）。
- 离屏容器：`position:fixed; left:-99999px; width:780px; padding:32px 40px; background:#fff`，注入 body。
- `html2canvas(container, { scale: 2, backgroundColor: "#fff", useCORS: true })`，`toBlob` 得 PNG。
- Tauri：`save` 对话框选路径，`write_binary_file` 写入；浏览器：`downloadBlob` 下载。
- `finally` 移除离屏容器。

新增依赖：`html2canvas@^1.4.1`。

### 验收
- 导出菜单点「导出长图（PNG）」，弹出保存对话框
- 生成的 PNG 为完整文档长图，2x 清晰度
- 代码块 / 公式 / 表格 / 图片均正确渲染

## 任务 39：文档大纲导出

### 目标
只导出标题层级，生成带缩进列表 + 原始标题结构的 md 文件，当目录用。

### 技术方案

修改 [exporter.ts](file:///workspace/src/lib/exporter.ts)：新增 `exportOutline`。

```typescript
export async function exportOutline(): Promise<void>
```

实现：
- `parseOutline(currentContent)` 复用现有大纲解析（[outline.ts](file:///workspace/src/lib/outline.ts)），得到 `{ level, text, slug }[]`。
- 生成内容：首行 `# {name} 目录`，逐条按 `level-1` 缩进 2 空格的列表项；末尾 `---` 分隔后附原始 `#` 语法标题结构，便于直接作为新文档骨架。
- Tauri：`save` 对话框写文件；浏览器：下载。

### 验收
- 导出菜单点「导出大纲（仅标题）」
- 生成的 md 文件含层级缩进列表 + 原始标题语法
- 无标题的文档生成空目录

## 任务 40：多窗口

### 目标
文件树 / 标签页右键「在新窗口打开」，Tauri 多窗口在独立窗口打开文件。

### 技术方案

新建 [newWindow.ts](file:///workspace/src/lib/newWindow.ts)：

```typescript
export const NEW_WINDOW_FILE_KEY = "inklingFile";
export function getNewWindowFilePath(): string | null;
export async function openInNewWindow(filePath: string): Promise<boolean>;
```

实现：
- `openInNewWindow`（仅 Tauri）：动态 `import("@tauri-apps/api/webviewWindow")` 的 `WebviewWindow`。以当前窗口 `origin + pathname` 为基础 URL，附加 `?inklingFile=<encoded>`，创建唯一 label（`inkling-{timestamp}-{rand}`）的新窗口，标题为文件名。
- `getNewWindowFilePath`：从 `URLSearchParams` 读取并解码，主窗口返回 null。
- 浏览器端 `openInNewWindow` 返回 false，调用方回退（文件树回退到 `openFile` 新 tab；标签页提示「多窗口仅在桌面端可用」）。

修改 [App.tsx](file:///workspace/src/App.tsx)：启动时 `useEffect` 读取 `getNewWindowFilePath()`，非空则 `openFileStandalone(target)`（单文件模式打开）。

修改 [Sidebar.tsx](file:///workspace/src/components/Sidebar/Sidebar.tsx) 的 `TreeContextMenu`：Markdown 文件新增「在新窗口打开」项。

修改 [TabContextMenu.tsx](file:///workspace/src/components/Tabs/TabContextMenu.tsx)：新增「在新窗口打开」项。

修改 [capabilities/default.json](file:///workspace/src-tauri/capabilities/default.json)：`windows` 加 `inkling-*` 通配，`permissions` 加 `core:window:allow-create` / `core:webview:allow-create-webview-window`，确保子窗口有同等权限。

### 验收
- 文件树 md 右键「在新窗口打开」，弹出独立窗口并自动打开该文件
- 标签页右键同样可「在新窗口打开」
- 多窗口各自独立编辑、保存
- 浏览器端回退提示或新 tab

## 调研后 defer 的功能

### 多光标编辑 / 块选模式（不做）

**调研结论**：ProseMirror 作者 Marijn Haverbeke 在官方论坛明确表示 Sublime 式多光标「very hard」——需自定义 `Selection` 子类并完整重写输入处理逻辑（typing / backspace / 键盘移动均需支持多 range），社区无现成实现。ProseMirror 唯一内置的多范围选择是表格的 `CellSelection`（本项目已支持表格多选）。矩形块选在 Markdown 文档场景几乎用不到，ROI 极低。

**决定**：不实现。如未来 Milkdown / ProseMirror 上游提供多光标能力再评估。

### 内置图床（defer）

**调研结论**：内置图床需后端对象存储（S3 / OSS / COS）或第三方图床（sm.ms / GitHub Issues）账号与凭证管理，与本项目「本地优先、免账号、绿色免安装」核心理念冲突，且引入网络依赖与凭证安全风险。

**现状**：[image-upload.ts](file:///workspace/src/components/Editor/image-upload.ts) 已提供完善本地方案——拖拽 / 粘贴图片自动存入工作区 `assets/` 并插入相对路径，整个工作区可随文件夹迁移，离线可用。

**决定**：defer。未来可作为可选插件接入，由用户自行配置图床凭证，不影响本地优先主流程。
