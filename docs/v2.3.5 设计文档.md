## 问题一：专注模式复合块不高亮（issue #56）

### 根因

高亮由两部分配合实现，二者粒度不一致导致列表/表格命中不到：

1. `editor-modes.ts` 的 ProseMirror 装饰用 `findParentNodeClosestToPos((n) => n.isBlock)` 取「光标所在的最内层块节点」。在列表（`bullet_list > list_item > paragraph`）和表格（`table > table_row > table_cell > paragraph`）里，命中的是**内部的 paragraph**，而非用户感知的「列表项/表格整体」。
2. `App.css` 只高亮 `.ProseMirror` 的**直接子节点**：`.focus-mode .ProseMirror > *` 弱化所有顶层块、`.focus-mode .ProseMirror > .inkling-focused` 仅高亮直接子节点中带 `inkling-focused` 的。列表/表格是直接子节点，但装饰加在了它们内部嵌套的 paragraph 上，选择器匹配不到。

结果：列表/表格永远停在弱化态，点不亮；段落/标题因本身就是直接子节点而正常。

### 修复（[editor-modes.ts](../src/components/Editor/editor-modes.ts)）

装饰目标从「最内层块」改为「文档顶层块」——取光标所在 `.ProseMirror` 直接子节点（深度 1，`$head.node(1)`），使装饰粒度与 CSS 高亮粒度一致：

```ts
if ($head.depth < 1) return DecorationSet.empty;
const top = $head.node(1);
const start = $head.before(1);
return DecorationSet.create(state.doc, [
  Decoration.node(start, start + top.nodeSize, { class: "inkling-focused" }),
]);
```

效果：列表 → `bullet_list`/`ordered_list`，表格 → `table`，段落 → `paragraph`，均正确点亮。

### 测试（[editor-modes.test.ts](../tests/unit/editor-modes.test.ts)）

无头 Milkdown（commonmark + gfm）驱动真实 schema 解析，断言装饰落在 top-level 块上，覆盖 5 个用例：段落、无序列表、有序列表、表格、关闭专注模式。

## 问题二：search.rs 单测（issue #47）

`search_in_workspace` 同时做「递归遍历工作区 + 正则匹配」，边界全靠人工兜底。新增 `#[cfg(test)]` 模块（复用 `mod.rs` 既有临时目录模式，不引入 tempfile），覆盖 9 个用例：

| 用例 | 断言 |
| --- | --- |
| `empty_query_returns_empty` | 空查询返回空 `Vec` 而非报错 |
| `missing_workspace_returns_error` | root 不存在返回 `Err` 含「工作区不存在」 |
| `case_sensitive_toggle` | 大小写敏感精确命中；忽略大小写命中全部 |
| `invalid_regex_returns_error` | 非法正则返回 `Err` 含「正则编译失败」，不 panic |
| `line_and_path_correctness_across_files` | 跨 3 文件行号从 1 开始、路径为完整绝对路径 |
| `hidden_directories_are_skipped` | `.hidden/` 内文件不被命中 |
| `non_utf8_file_is_skipped_silently` | GBK 乱码文件静默跳过，不计命中也不 panic |
| `column_counts_utf8_characters` | 列号按 UTF-8 字符计（中文+emoji 前导 → 列号 4） |
| `plain_text_query_escapes_regex_metacharacters` | 纯文本模式 `.` 被转义为字面量 |
| `oversized_file_is_skipped` | 超过 `MAX_FILE_SIZE` 的文件被跳过 |

## 问题三：pandoc.rs 单测（issue #48）

### 重构：参数拼装与执行分离

原 `pandoc_export_docx` 内联构造命令，无法脱离真实 pandoc 断言参数。拆成两个纯函数 + 一个执行函数：

- `build_pandoc_command(temp_md, output_path, resource_dir)`：拼装参数，`--resource-path` 仅当目录真实存在才追加，否则静默忽略；
- `build_pandoc_locate_command()`：返回 `where`/`which pandoc` 命令；
- `run_pandoc(cmd)`：执行并统一错误映射（IO 失败 →「执行 pandoc 失败」；非零退出码 →「pandoc 转换失败」+ stderr）。

### 测试（注入假脚本，无需 CI 装 pandoc）

| 用例 | 断言 |
| --- | --- |
| `locate_command_targets_pandoc` | Windows 用 `where`、类 Unix 用 `which`，参数 `pandoc` |
| `resource_dir_valid_dir_appends_flag` | 合法目录追加 `--resource-path <dir>`，基础参数不变 |
| `resource_dir_non_dir_is_safely_ignored` | 文件/不存在路径/空串均不追加 flag，不报错 |
| `missing_pandoc_returns_exec_failure` | 不存在的二进制 →「执行 pandoc 失败」 |
| `non_zero_exit_returns_conversion_failure` | 假脚本退出码 1 →「pandoc 转换失败」+ stderr |
| `zero_exit_returns_ok` | 退出码 0 → 成功 |
