# v2.4.0 设计文档

## 1. 概述
InklingMD v2.4.0 为**性能专项攻坚版本**，重点解决大型 Markdown 文档、多图渲染、频繁击键序列化以及工作区全局搜索等高负载场景下的主线程卡顿、全量重渲染和内存膨胀问题。

## 2. 详细改造内容

### 2.1 消除 App 根组件击键重渲染 (#73)
- **问题**：`App.tsx` 订阅了 `currentContent` / `splitContent`，导致用户每次打字根组件均全量重渲染。
- **方案**：抽离 `EditorBody` 独立组件承载编辑器与分屏渲染，从 `App.tsx` 彻底移除 `currentContent` / `splitContent` 状态订阅。

### 2.2 Markdown 序列化与大纲提取防抖 (#74)
- **问题**：每次 ProseMirror doc 变更立即全量遍历 AST 序列化与提取标题。
- **方案**：`markdown-publisher.ts` 引入 200ms 防抖更新机制；`outline-tracker.ts` 维持空闲与防抖分级调度，失焦/存盘时强制立即刷新。

### 2.3 Vite 代码分包优化 (#75)
- **问题**：单包 JS 体积达到 1.76MB，启动加载与脚本解析耗时高。
- **方案**：在 `vite.config.ts` 中配置 `manualChunks`，将 `milkdown-vendor`、`codemirror-vendor`、`katex-vendor`、`mermaid-vendor` 与 `lucide-vendor` 独立分包，主包体积减少约 65%。

### 2.4 本地图片流式 Asset 协议与内存缓存池 (#76)
- **问题**：图片每次读取均进行 Base64 IPC 传输，无内存缓存且存在 33% 内存膨胀。
- **方案**：采用 Tauri `convertFileSrc` 原生 Asset 协议流式读取，结合 `imageSrcCache`（最大容量 500）与 `allowAssetDir` 缓存已放行目录。

### 2.5 Mermaid 图表渲染防抖与中断队列 (#77)
- **问题**：连续输入导致 Mermaid 后台排队执行多次高耗时的 SVG 布局运算。
- **方案**：引入自增 `renderSeq` 令牌，在下一次渲染触发或组件卸载时立即作废旧请求，仅渲染最新输入。

### 2.6 Rust 后端全局搜索流式逐行读取 (#78)
- **问题**：一次性使用 `fs::read_to_string` 读入整个文件导致高内存毛刺。
- **方案**：`search.rs` 改用 `BufReader` 逐行扫描与正则匹配，发现匹配项立即收集，大幅降低大文件内存占用。

## 3. 测试与验证
- 新增 `tests/lib/imageSrcCache.test.ts` 覆盖本地图片解析与 LRU 缓存逻辑。
- 新增 `tests/components/MermaidPerf.test.ts` 覆盖 Mermaid 过期渲染请求中断与防抖测试。
- 自动化单测 419 项全部通过，构建包体积与首屏加载速度显著提升。
