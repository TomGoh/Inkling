## 任务 1：万行 MD 文档滚轮失效修复

### 目标

修复用户反馈的「使用万行 MD 文件测试时浏览器滚轮失效」问题：在大型文档下，鼠标滚轮滚动完全无响应或严重卡顿。

### 问题根因

v1.2.2 引入的 `Ctrl/Cmd+滚轮` 缩放文档功能，在 [App.tsx](file:///workspace/src/App.tsx) 中注册了一个 `passive: false` 的 wheel 监听器（capture 阶段），**常驻 window**：

```typescript
// 旧逻辑（v1.2.2 ~ v1.2.3）
useEffect(() => {
  const onWheel = (e: WheelEvent) => {
    if (!(e.ctrlKey || e.metaKey)) return; // 非 Ctrl 直接放行
    // ... 缩放逻辑
  };
  window.addEventListener("wheel", onWheel, { passive: false, capture: true });
  return () => window.removeEventListener("wheel", onWheel, ...);
}, []);
```

虽然 `onWheel` 内部对非 Ctrl 事件直接 return，但 **`passive: false` 本身就是性能陷阱**：

1. **浏览器合成线程无法快速处理滚动**：`passive: false` 告诉浏览器「我可能要 preventDefault」，浏览器必须等主线程执行完 `onWheel` 才能决定是否滚动。即使 `onWheel` 内部不调用 `preventDefault`，浏览器也无法提前知道，必须串行等待。
2. **主线程被阻塞时滚轮失效**：万行文档下，ProseMirror 的 DOM 渲染、Milkdown 的 `markdownUpdated` 序列化、代码块 NodeView 等会占用主线程。当主线程繁忙时，wheel 事件堆积在事件队列中，用户感知就是「滚轮完全失效」。
3. **capture 阶段放大阻塞**：capture 监听器比 bubble 监听器更早执行，阻塞窗口更长。

### 技术方案

**核心思路**：仅在 Ctrl/Cmd 键按下时才挂载 `passive: false` 监听器，普通滚动时 window 上无任何 wheel 监听器，让浏览器走合成线程快速滚动路径。

#### 1.1 抽取 useCtrlWheelZoom hook

新建 [src/lib/useCtrlWheelZoom.ts](file:///workspace/src/lib/useCtrlWheelZoom.ts)，将 wheel 逻辑从 App.tsx 内联的 useEffect 抽出为独立 hook，便于单元测试覆盖：

```typescript
import { useEffect } from "react";
import { useSettings, ZOOM_STEP } from "../store/settings";

export function useCtrlWheelZoom(): void {
  useEffect(() => {
    let ctrlHeld = false;

    const onWheel = (e: WheelEvent) => {
      const target = e.target as HTMLElement | null;
      if (target?.closest("[data-mermaid]")) return; // Mermaid 自管缩放
      e.preventDefault();
      useSettings.getState().adjustEditorZoom(
        e.deltaY < 0 ? ZOOM_STEP : -ZOOM_STEP,
      );
    };

    const onKeyDown = (e: KeyboardEvent) => {
      if ((e.ctrlKey || e.metaKey) && !ctrlHeld) {
        ctrlHeld = true;
        window.addEventListener("wheel", onWheel, {
          passive: false,
          capture: true,
        });
      }
    };
    const onKeyUp = (e: KeyboardEvent) => {
      if (!e.ctrlKey && !e.metaKey && ctrlHeld) {
        ctrlHeld = false;
        window.removeEventListener("wheel", onWheel, {
          capture: true,
        } as EventListenerOptions);
      }
    };
    const onBlur = () => {
      // 窗口失焦时重置（防止 Ctrl 按住时切窗导致监听器残留）
      if (ctrlHeld) {
        ctrlHeld = false;
        window.removeEventListener("wheel", onWheel, {
          capture: true,
        } as EventListenerOptions);
      }
    };

    window.addEventListener("keydown", onKeyDown);
    window.addEventListener("keyup", onKeyUp);
    window.addEventListener("blur", onBlur);
    return () => {
      window.removeEventListener("keydown", onKeyDown);
      window.removeEventListener("keyup", onKeyUp);
      window.removeEventListener("blur", onBlur);
      if (ctrlHeld) {
        window.removeEventListener("wheel", onWheel, {
          capture: true,
        } as EventListenerOptions);
      }
    };
  }, []);
}
```

App.tsx 改为一行调用：

```typescript
useCtrlWheelZoom();
```

#### 1.2 状态机说明

| 状态 | 触发 | wheel 监听器 | 行为 |
|---|---|---|---|
| 初始（ctrlHeld=false） | 组件挂载 | 无 | 普通滚动走浏览器合成线程快速路径 |
| Ctrl 按下 | keydown (ctrlKey/metaKey) | 挂载 passive:false capture | wheel 触发缩放，preventDefault 拦截浏览器原生缩放 |
| Ctrl 抬起 | keyup (!ctrlKey && !metaKey) | 卸载 | 回到初始状态 |
| 窗口失焦 | blur（Ctrl 按住时切窗） | 卸载 | 防止监听器残留导致下次切回时状态错乱 |
| 组件卸载 | useEffect cleanup | 卸载所有 | 无内存泄漏 |

#### 1.3 幂等性

`ctrlHeld` 标志位保证 Ctrl 多次重复按下只挂载一次 wheel 监听器：

```typescript
const onKeyDown = (e: KeyboardEvent) => {
  if ((e.ctrlKey || e.metaKey) && !ctrlHeld) { // !ctrlHeld 守卫
    ctrlHeld = true;
    window.addEventListener("wheel", onWheel, ...);
  }
};
```

#### 1.4 Mermaid 图表缩放排除

`onWheel` 内检查 `target.closest("[data-mermaid]")`，是则跳过文档缩放，让 Mermaid NodeView 自己的 wheel 监听接管图表缩放。这与 v1.2.3 的 Mermaid 缩放功能协作。

### 性能对比

| 场景 | 旧方案（passive:false 常驻） | 新方案（按需挂载） |
|---|---|---|
| 普通滚动（无 Ctrl） | 主线程繁忙时卡顿/失效 | 走合成线程快速路径，无阻塞 |
| Ctrl+滚轮缩放 | 正常 | 正常（与旧方案一致） |
| 万行文档普通滚动 | 严重卡顿，主线程被 wheel 队列阻塞 | 与无监听器一致，流畅 |

### 验收

- 万行 MD 文档普通滚动流畅，无卡顿/失效
- Ctrl+滚轮缩放功能正常（放大/缩小，50%~300%）
- Ctrl+0 重置缩放
- Mermaid 图表上 Ctrl+滚轮缩放图表，不触发文档缩放
- 切窗/卸载组件后无 wheel 监听器残留

## 任务 2：表格删列/删行按钮修复

### 目标

修复用户反馈的「工具栏表格删列按钮没用」问题：在表格内点击「删列/删行」按钮无任何效果。

### 问题根因

[TableToolbar.tsx](file:///workspace/src/components/Editor/TableToolbar.tsx) 的删列/删行按钮原本依赖 `deleteSelectedCellsCommand`，但该命令需要先有 `CellSelection`（选中整列/整行）才生效。工具栏按钮点击时用户只是把光标放在某个单元格内，并未选中整列，所以 `deleteSelectedCellsCommand` 实际是空操作。

### 技术方案

改用 `prosemirror-tables` 的 `deleteColumn` / `deleteRow`，这两个函数直接基于光标位置（`selection.$head`）计算所在列/行并删除，**无需先选中列**。

#### 2.1 导入

```typescript
import { deleteColumn, deleteRow } from "@milkdown/kit/prose/tables";
```

> 注：导入路径是 `@milkdown/kit/prose/tables`（Milkdown 7 的 prose 重导出），不是 `@milkdown/prose/tables`（旧路径会报 `Cannot find module`）。

#### 2.2 删列/删行实现

```typescript
// 删除当前列：直接用 prosemirror-tables 的 deleteColumn
// 无需先选中列（CellSelection），基于光标所在列位置删除
const deleteCol = () => {
  const editor = getEditor();
  if (!editor) return;
  editor.action((ctx) => {
    const view = ctx.get(editorViewCtx);
    deleteColumn(view.state, view.dispatch.bind(view));
    view.focus();
  });
};

// 删除当前行：直接用 prosemirror-tables 的 deleteRow
const deleteRow_ = () => {
  const editor = getEditor();
  if (!editor) return;
  editor.action((ctx) => {
    const view = ctx.get(editorViewCtx);
    deleteRow(view.state, view.dispatch.bind(view));
    view.focus();
  });
};
```

`deleteColumn(state, dispatch)` 的签名：传入当前 `EditorState` 和 `dispatch` 函数，内部计算光标所在列的 cell range，构造 transaction 并通过 dispatch 提交。

#### 2.3 按钮绑定

```tsx
<button className="tt-btn" onClick={deleteRow_} title="删除当前行">✕ 删行</button>
<button className="tt-btn" onClick={deleteCol} title="删除当前列">✕ 删列</button>
```

#### 2.4 与「删除表格」的区别

「删除整张表格」按钮仍走 `selectTableCommand` + `deleteSelectedCellsCommand`（先全选表格再删选中区域），这个流程对整表删除是正确的，保留不变：

```typescript
const deleteTable = () => {
  const editor = getEditor();
  if (!editor) return;
  editor.action((ctx) => {
    const commands = ctx.get(commandsCtx);
    commands.call(selectTableCommand.key);
    commands.call(deleteSelectedCellsCommand.key);
    ctx.get(editorViewCtx).focus();
  });
};
```

### 验收

- 光标放在表格某单元格，点击「删列」删除该光标所在列
- 光标放在表格某单元格，点击「删行」删除该光标所在行
- 删除后编辑器自动重新聚焦
- editor 不存在时点击按钮不抛错（静默无操作）
- 「删除整张表格」按钮仍正常工作

## 测试

### 新增 24 个测试用例

#### scroll-performance.test.ts（15 个）

[tests/unit/scroll-performance.test.ts](file:///workspace/tests/unit/scroll-performance.test.ts) 覆盖 `useCtrlWheelZoom` hook：

- 初始挂载时 window 上无 wheel 监听器（性能核心）
- Ctrl 按下挂载 wheel 监听器（passive:false, capture:true）
- Ctrl 抬起卸载 wheel 监听器
- Cmd（metaKey）按下也挂载（macOS 场景）
- Ctrl 按住时 wheel 向上滚放大、向下滚缩小
- 普通滚动（无 Ctrl）不触发缩放
- wheel 事件 preventDefault 拦截浏览器原生缩放
- Mermaid 图表区域 wheel 不触发文档缩放
- 窗口失焦清理残留监听器
- Ctrl 多次重复按下只挂载一次（幂等）
- 组件卸载清理所有监听器（无泄漏）
- 卸载后 wheel 不再触发缩放
- 缩放夹在 [0.5, 3] 范围
- **大文档场景：wheel 监听器数量恒定，不随文档节点数增长**（万行文档模拟）

#### TableToolbar.test.tsx（9 个）

[tests/components/TableToolbar.test.tsx](file:///workspace/tests/components/TableToolbar.test.tsx) 覆盖表格工具栏：

- inTable=false 不渲染表格上下文按钮

- 点击「删列」调用 `deleteColumn`（基于光标位置，无需先选列）
- 点击「删行」调用 `deleteRow`（基于光标位置，无需先选行）
- 点击「删除表格」先 selectTable 再 deleteSelectedCells（顺序校验）
- editor 不存在时点击删列/删行按钮不抛错（无操作）
- 对齐按钮调用 setAlignCommand
- 增行/增列按钮调用对应命令
