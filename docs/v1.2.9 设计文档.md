## 任务 1：表格列宽拖拽手柄不可见

### 背景

用户反馈「表格又没法用鼠标拖拽调整列宽了，印象一开始可以的」。

### 根因

`columnResizingPlugin`（prosemirror-tables 的 columnResizing）**装配正确、运行正常**（[Editor.tsx](file:///workspace/src/components/Editor/Editor.tsx) 第 14、245 行引入并 `.use()`），问题出在 [App.css](file:///workspace/src/App.css) 第 339-356 行：

- `.column-resize-handle` 被设为 `opacity: 0`（第 346、355 行），且 CSS 特异性高于标准 `tables.css` 的默认可见样式
- **缺少 `:hover` 显形规则**——手柄永远不可见
- 标准 `tables.css` 给手柄设了 `pointer-events: none`，手柄本身不接收鼠标事件，连 `cursor: col-resize` 光标提示也不生效

用户看不到拖拽手柄，也得不到任何交互暗示 →「拖不动列宽」。

### 修复

[App.css](file:///workspace/src/App.css) 补 hover 显形规则（第 357-365 行）：

```css
/* 悬停单元格时显示列宽拖拽手柄（手柄 pointer-events:none，靠 cell :hover 触发显形） */
.editor-scroll .milkdown th:hover .column-resize-handle,
.editor-scroll .milkdown td:hover .column-resize-handle {
  opacity: 0.5;
}
/* 拖拽进行中（ProseMirror 加 resize-cursor 类）手柄更明显 */
.editor-scroll .milkdown .ProseMirror.resize-cursor .column-resize-handle {
  opacity: 0.8;
}
```

同时把 `table { overflow: hidden }` 改为 `overflow: visible`（第 319-320 行），避免裁掉最右列手柄外伸的 2px。

### 不改的部分

- `Editor.tsx` 的 `columnResizingPlugin` 装配（正确）
- `tables.css` 标准样式引入（正确）
- `table-layout: fixed`（列宽拖拽必需）

### 已知限制

按 [v0.8.0 设计文档](file:///workspace/docs/v0.8.0 设计文档.md) 既定设计，列宽只在本会话有效，重开文件会丢失（markdown 不携带 `columnWidths` 属性）。这不是本次需修的问题。

## 任务 2：全部替换报错 "message not allowed by acl"

### 背景

用户反馈「全部替换时报错 message not allowed by acl」。

### 根因

`replaceAll` 本身是纯前端逻辑（[search.ts](file:///workspace/src/components/Editor/search.ts) 第 141-150 行直接 `view.dispatch(tr)` 改 doc，无 invoke），但改完文档触发自动保存链路：

1. `replaceAll` 改 doc → `onChange` → `setContent` 置脏 → 2s 防抖 `saveCurrent()` → `writeTextFile` invoke
2. `write_text_file` command 被 Tauri v2 ACL 拦截 → "message not allowed by acl"

[Tauri v2 的 ACL 对所有 command（含 app 自定义 command）强制校验](https://v2.tauri.app/security/scope/)。项目在 [lib.rs](file:///workspace/src-tauri/src/lib.rs) 第 76-90 行注册了 13 个自定义 command，但 [capabilities/default.json](file:///workspace/src-tauri/capabilities/default.json) 只授权了 6 条插件权限（core/opener/dialog），**13 个自定义 command 一个都没授权**。

这不只是「全部替换」的问题——打开文件、工作区、重命名、删除、全局搜索、导出 docx 等所有 fs 功能都会报同样的错。用户在「全部替换」上报只是因为替换动作显眼 + 紧接着 2s 后状态栏出现保存失败提示。

### 修复

Tauri v2 对 app 自定义 command **不会自动生成** `allow-<command>` 权限标识符（只有 plugin command 才自动生成）。app 自定义 command 必须在 `src-tauri/permissions/` 目录下用 TOML 显式定义权限，再由 capabilities 引用。

新增 [permissions/app-commands.toml](file:///workspace/src-tauri/permissions/app-commands.toml)，为 13 个 command 各定义一个 `[[permission]]` 块：

```toml
[[permission]]
identifier = "allow-write-text-file"
description = "Allow write_text_file command"
commands.allow = ["write_text_file"]
# ... 其余 12 个同理
```

[capabilities/default.json](file:///workspace/src-tauri/capabilities/default.json) 引用这些 identifier：

```json
"allow-list-dir",
"allow-read-text-file",
"allow-write-text-file",
"allow-write-binary-file",
"allow-file-mtime",
"allow-rename-path",
"allow-delete-path",
"allow-create-file",
"allow-create-dir",
"allow-search-in-workspace",
"allow-pandoc-check",
"allow-pandoc-export-docx",
"allow-take-pending-file"
```

> 注意：identifier 保留 command 函数名的下划线（`allow-write-text-file` 对应 `write_text_file`），不要转连字符。`commands.allow` 填的是 invoke_handler 注册的函数名。

### 验收

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 全部替换后自动保存 | 报 "message not allowed by acl" | 正常保存 |
| 打开文件 | 报错（read_text_file 被拦截） | 正常 |
| 工作区列表 | 报错（list_dir 被拦截） | 正常 |
| 导出 docx | 报错（pandoc_export_docx 被拦截） | 正常 |

## 任务 3：代码块点击第一行光标跳到 9-11 行

### 背景

用户反馈「代码块明明点击第一行光标却一直聚焦在第九，十，十一行」。

### 根因

[code-block-view.ts](file:///workspace/src/components/Editor/code-block-view.ts) 的 `setSelection`（第 345-351 行）没有把 ProseMirror 绝对位置翻译成 CodeMirror 本地位置：

```typescript
// 修复前（BUG）
setSelection(anchor: number, head: number) {
  this.cm.focus();
  this.cm.dispatch({ selection: { anchor, head } });  // ← 直接用 PM 绝对位置当 CM 本地位置
}
```

ProseMirror 调用 NodeView 的 `setSelection(anchor, head)` 时，传入的是**整个文档的绝对位置**（包含代码块之前所有内容）。但这里直接当作 CodeMirror 内部本地位置传给 `cm.dispatch`。

**反馈闭环**导致这个 bug 被激活：
1. 用户点击代码块第一行 → CM 原生把光标放到本地位置 0（正确）
2. CM 的 `forwardUpdate`（第 288-305 行）把 CM 选区转发给 PM：`selFrom = getPos()+1 + 0`
3. PM 应用事务，回调 NodeView 的 `setSelection(getPos()+1, getPos()+1)`
4. **BUG**：`setSelection` 把绝对位置 `getPos()+1`（如 203）当作 CM 本地位置传给 `cm.dispatch`
5. CM 把光标移到本地位置 203 → 约第 10 行（203 / 20 ≈ 10）

这与用户描述的「9/10/11 行」完全吻合——取决于代码块在文档中的位置（前面有多少内容）。

对比同文件的 `forwardUpdate`（第 290 行）做的是**正确**的反向转换：`offset = getPos() + 1`。`setSelection` 缺少相反方向的减法。

### 修复

[code-block-view.ts](file:///workspace/src/components/Editor/code-block-view.ts) 第 345-359 行，`setSelection` 做位置翻译：

```typescript
setSelection(anchor: number, head: number) {
  if (!this.cm) return;
  const pos = this.getPos();
  if (pos == null) return;
  // PM 绝对位置 → CM 本地位置（与 forwardUpdate 的 offset = getPos()+1 严格互逆）
  const docLen = this.cm.state.doc.length;
  const localAnchor = Math.max(0, Math.min(anchor - pos - 1, docLen));
  const localHead = Math.max(0, Math.min(head - pos - 1, docLen));
  this.cm.focus();
  this.updating = true;
  this.cm.dispatch({ selection: { anchor: localAnchor, head: localHead } });
  this.updating = false;
}
```

### 附带加固

1. **`selectNode`**（第 361-368 行）：NodeSelection 选中整个代码块时清空 CM 内残留的文本选区，避免视觉不一致
2. **`update()` 的 `scrollIntoView`**（第 339-341 行）：从 `true` 改为 `false`，外部受控更新（大纲跳转/全局替换）不再抢占视口滚动

### 验收

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 代码块非文档首块，点击第一行 | 光标跳到 9-11 行 | 光标在第一行 |
| 点击代码块任意中间行 | 光标跳到错误位置 | 光标落在所点击行 |
| 三击代码块（NodeSelection） | CM 残留旧选区 | CM 选区清空到 0 |
| 全局替换后 | 代码块乱滚动 | 不抢占视口 |
