## 1. 背景与目标

在 v2.6.1 版本发布后的多维度交叉 Review 中，发现并提炼出 10 项深度整改与防护加固任务。这些问题涵盖底层的并发写入安全性、大文件 IPC 通信效率、外部文件误删灾难恢复、时间戳精度断链、TypeScript 测试类型健壮性以及统一的原生对话框交互规范。

本次 v2.6.2 版本针对上述 10 项缺陷与防御缺口进行彻底闭环，消除全部隐藏风险，确保桌面端与 Web 端的绝对稳定性。

## 2. 核心问题与架构整改

### 2.1 P0：Rust 底层原子写盘与临时文件唯一性（任务 1 & 10）
- **问题根因**：原 `write_binary_file`、`write_text_file` 与 Pandoc 临时文件生成逻辑中，临时文件名仅使用静态前缀或简单时间戳，在多窗口并发、批量并发保存或极端并发重载下存在临时文件同名碰撞风险；且部分写入路径未显式调用 `sync_all()`，断电或系统崩溃时存在文件截断为 0 字节的隐患。
- **架构决策**：
  - 引入 `PID + Unix纳秒/微秒时间戳 + 全局原子自增计数器 (AtomicU64)` 生成绝对唯一的临时文件路径。
  - 在执行原子替换（`fs::rename`）前，强制执行 `file.sync_all()`，确保数据真实落盘至物理介质后再完成重命名操作。

### 2.2 P0：大文件 IPC 二进制分块传输（任务 2）
- **问题根因**：前端直接将超大 `Uint8Array`（如高清大图、大型二进制导出物）转为普通数组通过 Tauri IPC 传递，会导致庞大的 JSON 序列化膨胀以及 JavaScript 调用栈溢出（`Maximum call stack size exceeded`）。
- **架构决策**：
  - 前端 `writeBinaryFile` 与 `exporter.ts` 采用 `0x8000`（32KB）分块处理机制转换为 Base64 编码字符串。
  - Rust 后端新增专用 Base64 解码写入逻辑，大幅降低 IPC 传输损耗与内存驻留。

### 2.3 P0：外部删除文件内存快照恢复机制与 UI（任务 3）
- **问题根因**：当打开的文件在外部被意外删除时，虽然本地有保护快照，但缺乏可视化恢复入口，用户难以找回未保存的内容。
- **架构决策**：
  - 在 Workspace Store 中完善快照管理：`loadDeletedSnapshots`、`clearDeletedSnapshots`、`removeDeletedSnapshot` 及 `openUntitledTabWithContent`。
  - 新增 `src/components/Sidebar/DeletedSnapshots.tsx` 恢复面板与图标，当检测到外部删除快照时在侧边栏明确提示，支持一键恢复为未命名标签页或单个/批量清理。

### 2.4 P1：毫秒级 mtime 精度对齐与保存冲突 Fast-Path（任务 4 & 5）
- **问题根因**：Rust 后端 `file_mtime` 原先返回浮点秒（`as_secs_f64()`），而前端按毫秒语义进行了容差修改（`< 5`），导致了长达 5 秒的漏检盲区；此外，保存操作缺少基于 mtime 的轻量快速路径。
- **架构决策**：
  - Rust 端 `file_mtime_sync` 彻底改为 Unix 毫秒时间戳（`.as_millis() as f64`），并在前端全面保持 Unix 毫秒语义一致性。
  - `useFileWatcher` 防抖时间容差精准收紧至 `< 5ms`。
  - `saveCurrent` 引入 `diskMtime` 内存缓存比对：若磁盘修改时间与本地记录一致，则判定未发生外部并发修改，直接安全覆写，跳过无谓的弹窗确认流程。

### 2.5 P1：自定义 CSS 持久化与启动静默降级（任务 6）
- **问题根因**：用户配置的自定义 CSS 路径未随配置持久化，重启应用后失效；若引用的外部 CSS 文件被删除，可能导致应用启动时白屏或抛出未捕获异常。
- **架构决策**：
  - 自定义 CSS 路径纳入全局 JSON 配置文件进行持久化保存。
  - 应用初始化时调用 `initCustomCSS`，若文件不存在或读取失败，执行静默优雅降级，并在 UI 上重置为未设置状态，绝不阻塞应用正常渲染。

### 2.6 P1：TypeScript 测试类型全量严格健全（任务 7）
- **问题根因**：`tsconfig.json` 此前未包含 `tests/` 目录，导致测试文件中存在大量隐性类型错误、类型断言缺失，甚至使用 `any` 绕过类型检查。
- **架构决策**：
  - `tsconfig.json` `include` 显式纳入 `"tests"` 目录。
  - 全面修复 `tests/` 下 50+ 个测试文件的类型定义（ProseMirror 选区/Doc、CodeMirror、Tauri IPC Mock、Window 对象等），杜绝任何类型忽略注解，实现 `npx tsc --noEmit` 0 报错。

### 2.7 P2：搜索忽略目录双端对齐与深度限制（任务 8）
- **问题根因**：前端与 Rust 搜索忽略列表不同步，且 Rust 端缺少遍历递归深度上限，在符号链接或深层递归目录下存在栈溢出风险。
- **架构决策**：
  - 提取统一的 `searchIgnore.ts`，前后端对齐忽略规则（`.git`, `node_modules`, `dist`, `.target` 等）。
  - Rust 搜索模块增加 `MAX_SEARCH_DEPTH = 64` 防御性层级深度限制。

### 2.8 P2：统一原生对话框封装（任务 9）
- **问题根因**：全工程散落着 `window.confirm` 和 `window.alert` 调用，不仅破坏桌面原生质感，且在部分平台存在阻断事件循环的问题。
- **架构决策**：
  - 封装 `src/lib/dialogs.ts`（`showMessage` 与 `askConfirmation`）。
  - 桌面端无缝接入 Tauri `@tauri-apps/plugin-dialog` 原生对话框，Web/Mock 模式下平滑降级为浏览器标准对话框。
